# 도메인 개요

## 제품

Contentria는 회원이 블로그를 만들고 글을 발행하는 플랫폼이다.
독자는 글을 읽고, 블로그를 구독하고, 댓글과 좋아요를 남긴다.

## 전제

경계 판단의 근거가 되는 제품 결정이다. 바뀌면 03과 04를 다시 검토한다.

| # | 전제 | 영향 |
|---|---|---|
| 1 | 블로그는 1인 소유다. 다중 작성자 계획은 없다 | 글의 작성자는 항상 블로그 소유자다 |
| 2 | 한 회원이 블로그를 여러 개 가질 수 있다 | 작성자의 이름과 사진은 블로그가 아니라 회원에 속한다 |
| 3 | 구독 대상은 블로그다 | 같은 회원의 다른 블로그는 따로 구독한다 |
| 4 | 댓글은 로그인한 회원만 쓴다 | 댓글 작성자는 회원으로 식별한다 |
| 5 | 블로그 소유자가 댓글을 삭제하거나 숨기는 기능은 당장 없다 | 상호작용이 출판에서 필요한 정보가 좁다 |
| 6 | 관리자는 모든 블로거를 일괄 관리하는 플랫폼 운영자다 | 블로그 소유자와 다른 행위자다 |
| 7 | 관리자에게 신고나 제재 같은 별도 규칙은 당장 없다 | 운영 컨텍스트를 두지 않는다 |

## 행위자

블로거와 독자는 계정의 종류가 아니라 같은 회원이 맡는 역할이다.

| 행위자 | 정의 |
|---|---|
| 블로거 | 블로그를 하나 이상 소유한 회원 |
| 독자(비로그인) | 로그인하지 않고 글을 읽는 사람 |
| 독자(로그인) | 글을 읽고 구독, 댓글, 좋아요를 하는 회원 |
| 관리자 | 플랫폼 전체를 관리하는 운영자 |
| 시스템 | 정해진 시각이나 메시지에 따라 동작하는 처리 (영상 변환, 정리, 집계) |

## 유스케이스

| 상태 | 뜻 |
|---|---|
| 현재 | 새 구조의 코드에 있다 |
| 계획 | 맡을 컨텍스트는 정했고, 아직 만들지 않았다 |
| 보류 | 레거시에는 있었지만 새 구조에서는 범위 밖으로 두었다. 필요할 때 정한다 |

| 행위자 | 유스케이스 | 상태 | 컨텍스트 |
|---|---|---|---|
| 블로거 | 가입, 이메일 인증, 로그인, 코드 로그인, 소셜 로그인 | 현재 | 회원 |
| | 비밀번호 재설정 | 현재 | 회원 |
| | 표시 이름 변경 | 현재 | 회원 |
| | 계정 설정 (로그인 방법 연동과 해제, 비밀번호 변경, 이메일 변경, 탈퇴) | 현재 | 회원 |
| | 블로그 생성 (샘플 카테고리와 샘플 글 포함) | 현재 | 출판 |
| | 블로그 설정 수정 (제목, 설명) | 현재 | 출판 |
| | 카테고리 구성 변경 | 현재 | 출판 |
| | 글 작성, 수정, 삭제 | 현재 | 출판 |
| | 이미지, 영상 업로드 | 현재 | 미디어 |
| | 블로그 대시보드 조회 (방문자, 조회수, 인기 글) | 현재 | 분석 + 출판 (조회 조합) |
| 독자(비로그인) | 블로그 홈, 글 목록, 글 상세, 최근 글 조회 | 현재 | 출판 |
| | 댓글, 좋아요 수, 구독자 수 조회 | 현재 | 상호작용 |
| | 방문 기록 | 현재 | 분석 |
| 독자(로그인) | 블로그 구독, 구독 해지, 구독 목록 조회 | 현재 | 상호작용 |
| | 댓글과 답글 작성, 수정, 삭제 | 현재 | 상호작용 |
| | 좋아요, 좋아요 취소, 좋아요한 글 조회 | 현재 | 상호작용 |
| | 알림 수신, 읽음 표시 | 현재 | 알림 |
| 관리자 | 전체 블로거 조회, 관리자 대시보드 | 계획 | 회원 + 출판 + 분석 (조회 조합) |
| 시스템 | 영상 변환 | 현재 | 미디어 |
| | 버려진 업로드와 삭제된 영상 정리 | 현재 | 미디어 |
| | 일별 통계 집계 | 현재 | 분석 |
| | 만료된 토큰과 인증 시도 정리 | 보류 | 회원 |
| | 보존 기간이 지난 알림 정리 | 현재 | 알림 |

## 서브도메인

| 서브도메인 | 분류 | 이유 |
|---|---|---|
| 출판 | 핵심 | 제품이 존재하는 이유다. 글을 쓰고 발행하는 경험이 차별점이 된다 |
| 상호작용 | 지원 | 블로그 플랫폼에 흔한 기능이지만 구독과 알림의 연결처럼 제품에 맞춘 규칙이 필요하다 |
| 미디어 | 지원 | 업로드, 이미지 정제, 영상 변환을 직접 구현했지만 차별점은 아니다. 외부 서비스로 대체할 수 있다 |
| 분석 | 지원 | 블로그 대시보드와 관리자 대시보드에 숫자를 공급한다 |
| 회원 | 일반 | 가입, 인증, 프로필은 어느 서비스에나 있다 |
| 알림 | 일반 | 발송 수단과 기록은 어느 서비스에나 있다 |

### 분류가 주는 지침

| 분류 | 지침 |
|---|---|
| 핵심 | 도메인 모델에 가장 많이 투자한다. 규칙을 애그리거트 안에 둔다 |
| 지원 | 필요한 만큼만 모델링한다. 단순한 구조로 시작한다 |
| 일반 | 표준적인 방식을 따른다. 검증된 라이브러리나 외부 서비스를 먼저 검토한다 |

일반은 차별점이 아니라는 뜻이지 대충 만들어도 된다는 뜻이 아니다.
회원의 인증 규칙은 보안에 직결되므로 [contexts/member/01-rules.md](../contexts/member/01-rules.md)에 따로 정리했다.
