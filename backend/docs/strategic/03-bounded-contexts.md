# 바운디드 컨텍스트

[01-domain-overview.md](01-domain-overview.md)의 전제와 [02-ubiquitous-language.md](02-ubiquitous-language.md)의 용어를 따른다.

## 목록

| 컨텍스트 | 영문 이름 | 책임 | 애그리거트 | 서브도메인 |
|---|---|---|---|---|
| 회원 | member | 가입, 인증, 계정 상태, 프로필 | Account (멤버: Credential, Role), Profile | 일반 |
| 출판 | publishing | 블로그, 카테고리, 글의 작성과 발행 | Blog, CategoryTree (멤버: Category), Post (멤버: PostSlug) | 핵심 |
| 상호작용 | interaction | 블로그 구독, 댓글, 좋아요 | Subscription, Comment, Like | 지원 |
| 미디어 | media | 이미지와 영상의 업로드, 정제, 변환, 정리 | Media, Video | 지원 |
| 분석 | analytics | 방문 기록, 조회수, 통계 집계 | Visit, DailyStatistics | 지원 |
| 알림 | notification | 다른 컨텍스트의 사건을 회원에게 알림 | Notification | 일반 |

영문 이름은 코드의 컨텍스트 이름과 문서 폴더 이름(`contexts/<영문 이름>`)으로 쓴다.

## 소유하는 것과 소유하지 않는 것

| 컨텍스트 | 소유한다 | 소유하지 않는다 (소유자) |
|---|---|---|
| 회원 | 계정, 자격증명, 권한, 계정 상태, 표시 이름, 프로필 사진 | 블로그 소유 관계 (출판) |
| 출판 | 블로그와 소유자, 카테고리 구성, 글 본문과 상태, 본문 형식(마크다운) | 조회수 (분석), 좋아요 수 (상호작용), 작성자 이름과 사진 (회원), 파일 저장 (미디어) |
| 상호작용 | 구독 관계, 댓글, 좋아요, 좋아요 수 | 글 공개 여부 (출판), 댓글 작성자 이름 (회원) |
| 미디어 | 파일, 저장 위치, 업로드와 변환 상태, 파일과 글의 연결 | 본문에서 어떤 파일을 참조하는지 판단 (출판) |
| 분석 | 방문 기록, 조회수, 방문자 수, 일별 통계 | 글 제목과 슬러그 (출판) |
| 알림 | 알림 기록 | 알림의 계기가 된 사건 (발행한 컨텍스트) |

## 경계를 나눈 기준

**컨텍스트는 애그리거트 단위가 아니다.**
애그리거트는 한 트랜잭션에서 일관성을 지키는 단위이고, 컨텍스트는 하나의 모델과 언어가 통하는 범위다.
컨텍스트 하나에 애그리거트가 여러 개 있을 수 있다.

같은 컨텍스트로 묶는 조건은 다음과 같다.

| 기준 | 질문 |
|---|---|
| 언어 | 같은 단어가 같은 뜻으로 쓰이는가 |
| 함께 바뀌는 규칙 | 한 유스케이스가 여러 애그리거트를 즉시 일관되게 바꿔야 하는가 |
| 변경 이유 | 같은 행위자가 같은 이유로 바꾸는가 |

## 결정과 이유

### 애그리거트마다 컨텍스트를 두던 방식을 버린다

**이전 결정:** 계정, 프로필, 블로그, 글, 댓글, 미디어, 영상, 구독, 알림을 각각 컨텍스트로 두었다. 컨텍스트마다 애그리거트가 하나씩이었다.

**뒤집은 이유:** 이 기준으로 나눈 레거시 코드에서 다음 현상이 나타났다. 근거는 [05-legacy-mapping.md](05-legacy-mapping.md)에 있다.

- 블로그, 카테고리, 글이 서로를 호출하는 순환이 생겼다.
- 블로그 생성처럼 여러 애그리거트를 즉시 함께 바꿔야 하는 유스케이스가 "컨텍스트를 넘는 트랜잭션"이 되었다.
- 화면에 필요한 회원 정보가 계정의 민감 정보와 함께 모든 곳으로 퍼졌다.

나뉘어 있어야 할 것이 하나로 묶여 있고, 하나여야 할 것이 나뉘어 있었다.

### 계정과 프로필을 하나의 회원 컨텍스트로 묶는다

**이전 결정:** 접근 패턴과 민감도가 다르다는 이유로 계정과 프로필을 별도 컨텍스트로 두었다.

| | 계정 | 프로필 |
|---|---|---|
| 담는 것 | 이메일, 상태, 자격증명, 권한 | 표시 이름, 사진 |
| 민감도 | 높음 | 공개 |
| 읽는 빈도 | 인증할 때 | 글, 댓글을 보여줄 때마다 |
| 읽는 주체 | 본인 | 누구나 |

**뒤집은 이유:** 이 차이는 사실이지만 컨텍스트가 아니라 애그리거트를 나눌 이유다.

| 기준 | 계정과 프로필 |
|---|---|
| 언어 | 둘 다 "회원" 한 사람을 말한다. 단어의 뜻이 갈리지 않는다 |
| 함께 바뀌는 규칙 | 가입할 때 함께 만들어진다 |
| 생명주기 | 계정이 탈퇴하면 프로필도 함께 정리된다 |

계정과 프로필은 회원 컨텍스트 안의 서로 다른 애그리거트로 둔다.
다른 컨텍스트에는 프로필 조회만 공개하고 계정은 공개하지 않는다. 민감도 차이는 이것으로 해결된다.

### 블로그, 카테고리, 글을 하나의 출판 컨텍스트로 묶는다

- 같은 블로거가 같은 이유(자기 블로그를 꾸리는 일)로 바꾼다.
- 블로그를 만들 때 샘플 카테고리와 샘플 글을 즉시 함께 만든다.
- 카테고리를 지우려면 그 카테고리에 글이 있는지 알아야 하고, 글을 쓰려면 카테고리가 같은 블로그에 속하는지 알아야 한다.
- 1인 블로그이므로 글의 작성자는 블로그 소유자다. 글과 블로그가 "작성자"라는 개념을 공유한다.

### 조회수는 분석이 소유한다

- 무엇을 조회 1회로 셀지(30분 안의 재방문 제외)는 분석의 규칙이다. 셈 규칙을 가진 쪽이 숫자를 소유한다.
- 글의 규칙 중 조회수에 의존하는 것은 없다. 글에 조회수를 넣으면 지킬 규칙 없이 결합만 생긴다.
- 조회는 독자가 글을 열 때마다 발생한다. 이를 글의 변경으로 다루면 독자의 읽기가 출판의 쓰기가 된다.
- 관리자 대시보드는 블로그 경계를 넘어 집계한다. 분석에 있어야 한 곳에서 끝난다.

### 좋아요 수는 상호작용이 소유한다

좋아요는 통계가 아니라 회원의 행위다. "한 회원이 한 글에 한 번, 취소 가능"이라는 규칙이 있다. 규칙을 가진 상호작용이 수를 소유한다.

### 구독, 댓글, 좋아요를 하나의 상호작용 컨텍스트로 둔다

- 행위 주체가 같다. 로그인한 독자다.
- 의존하는 대상이 같다. 출판(대상의 존재와 공개 여부)과 회원(행위자의 상태)이다.
- 지금은 세 기능 모두 규칙이 작다.

댓글 관리 기능처럼 규칙이 따로 자라기 시작하면 그때 나눈다.

### 미디어는 여러 배포 단위에 걸친 하나의 컨텍스트다

영상은 업로드, 변환, 정리를 서로 다른 프로세스가 맡는다. 하지만 셋 모두 같은 영상 상태 규칙을 다룬다.
배포 단위와 컨텍스트는 다른 축이다. 상태 규칙은 미디어 컨텍스트의 모델 하나에 둔다.

### 관리자는 컨텍스트가 아니다

관리자는 새 도메인이 아니라 새 행위자다. 관리자가 하는 일은 기존 컨텍스트에 속한다.

| 관리자 행위 | 처리하는 컨텍스트 |
|---|---|
| 블로거 계정 정지 | 회원 |
| 글 숨김 | 출판 |
| 플랫폼 전체 통계 | 분석 |

관리자 기능은 별도 진입점에서 각 컨텍스트의 공개 기능을 호출한다.
신고 접수, 제재 이력, 이의 제기처럼 운영 규칙 자체가 생기면 운영 컨텍스트를 새로 둔다.

## 컨텍스트가 아닌 것

| 항목 | 처리 |
|---|---|
| 블로그 대시보드 | 분석과 출판의 조회 결과를 화면용으로 조합한다 |
| 관리자 대시보드, 관리 기능 | 별도 진입점. 회원, 출판, 분석의 공개 기능을 호출한다 |
| 요청 인증 처리 | 진입점의 관심사다. 토큰을 발급하는 규칙은 회원에 있다 |
| 공통 기반 (식별자 생성, 예외, 영속성 기반) | 공유 커널. 도메인 개념을 넣지 않는다 |

## 컨텍스트를 새로 만들거나 나누는 기준

새 개념이 나오면 먼저 기존 컨텍스트의 하위 개념으로 둔다. 다음 중 하나에 해당할 때 나눈다.

- 기존 컨텍스트와 같은 단어를 다른 뜻으로 써야 한다.
- 바꾸는 행위자나 바꾸는 이유가 다르다.
- 기존 컨텍스트와 즉시 일관될 필요가 없고 사건 통지로 충분하다.

**고유한 애그리거트가 있다는 것은 나눌 근거가 아니다.**

## 정하지 않은 것

| 항목 | 정할 시점 |
|---|---|
| 계정이 정지되거나 탈퇴하면 그 회원의 블로그와 글을 어떻게 보여줄지 | 관리자 기능을 만들 때 |

정한 것은 각 컨텍스트 문서로 옮겼다.

| 항목 | 정한 곳 |
|---|---|
| 탈퇴한 회원의 댓글 작성자 표시 | [interaction/01-rules.md](../contexts/interaction/01-rules.md)의 "다른 컨텍스트의 일로 생기는 것". 댓글은 남기고 화면이 회원의 탈퇴 표시로 보여준다 |
| 좋아요와 구독을 알림 대상으로 할지 | [notification/01-rules.md](../contexts/notification/01-rules.md)의 "보류". 지금은 하지 않는다 |
| 회원의 안내 메일을 알림이 보낼지 | [notification/01-rules.md](../contexts/notification/01-rules.md)의 전제 6. 회원이 계속 보낸다 |
