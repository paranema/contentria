# 로깅 규약

백엔드 로그의 레벨, 기록 대상, 메시지 형식 및 계층별 로깅 기준을 정의합니다.

## 로거 설정

SLF4J를 사용하며, 클래스마다 로거 인스턴스를 하나씩 둡니다.

```kotlin
private val log = LoggerFactory.getLogger(javaClass)
```

- 메시지의 동적 값은 자리표시자 `{}`를 사용합니다. 문자열 연결(`+`)을 사용하지 않습니다.
- 예외 객체는 마지막 인자로 전달하여 스택 트레이스를 보존합니다.

## 로그 레벨

### 레벨 분류

| 레벨 | 용도 | 예시 |
|---|---|---|
| `ERROR` | 시스템이 정상 동작할 수 없으며 즉각적인 조치가 필요한 상황 | DB 연결 실패, 필수 설정 누락 |
| `WARN` | 비정상 상황이지만 시스템은 동작하며 재시도나 다음 주기에 처리 가능한 상황 | 외부 큐 폴링 실패, 임시 파일 정리 실패, 안내 메일 발송 실패 |
| `INFO` | 운영 관점에서 인지해야 하는 주요 비즈니스 결과 | 배치 작업 실행 결과, 주요 도메인 상태 변경 |
| `DEBUG` | 개발 및 디버깅을 위한 세부 실행 흐름 | 내부 단계 완료, 조회 조건 |

운영 환경의 기본 루트 레벨은 `INFO`입니다 (`logging.level.root`). 미처리 예외는 프레임워크가 `ERROR`로 기록하므로, 비즈니스 코드에서는 주로 `WARN`과 `INFO`를 직접 기록합니다.

### 레벨 선택 흐름

```
시스템 장애로 처리가 중단되는가?           → ERROR
처리는 지속되며 재시도 가능한가?           → WARN
운영 관리에 필요한 업무 결과인가?          → INFO
그 외 개발 및 추적 목적의 흐름인가?        → DEBUG
```

### 흔한 주의 사항

| 잘못된 사용 | 올바른 사용 |
|---|---|
| 모든 API 요청을 INFO로 기록 | DEBUG로 기록합니다. INFO는 일일 발생량을 운영자가 검토할 수 있는 수준으로 제한합니다. |
| 내부 성공 단계마다 INFO 기록 | DEBUG로 기록합니다. 최종 업무 결과만 상위 계층에서 1회 INFO로 기록합니다. |
| 필수 설정 누락을 WARN으로 처리 | 시스템 구동이 불가능한 상태이므로 ERROR로 기록합니다. |

## 기록 대상 관리

### 기록 금지 항목

어떠한 로그 레벨에서도 아래 민감 데이터는 남기지 않습니다.

| 구분 | 금지 대상 | 대체 표기 |
|---|---|---|
| 인증 정보 | 토큰(액세스, 리프레시), API 키, 인증 코드 | 기록하지 않음 |
| 자격 증명 | 비밀번호(원문 및 해시) | 기록하지 않음 |
| 개인정보 | 이메일 주소, 전화번호 | 계정 ID(UUID) |
| 페이로드 | 요청 및 응답 본문 전체 | 리소스 식별자(글 ID, 블로그 ID 등) |
| 세션 정보 | 쿠키 값 전체 | 필요 시 쿠키 이름만 기록 |

> [!IMPORTANT]
> **이메일 주소 기록 금지**
> 이메일 주소는 개인정보 보호법 및 GDPR상 개인 식별 정보입니다. 로그 유출 시 기술 결함이 개인정보 유출 사고로 격상될 수 있으므로, 로그 식별자는 항상 UUID 형식의 계정 ID를 사용합니다.
> 예외 객체의 메시지에 이메일이 포함될 수 있는 경우, 메시지 대신 예외 클래스 이름만 기록합니다.
> ```kotlin
> log.warn("Account notice {} was not sent: {}", event.notice::class.simpleName, e.javaClass.name)
> ```

### 기록 허용 항목

| 항목 | 예시 |
|---|---|
| 고유 식별자 | 계정 ID, 글 ID, 블로그 ID, 미디어 ID (UUID) |
| 열거형 상태값 | 처리 상태, 오류 코드, 연동 공급자 종류 |
| 수치 정보 | 처리 건수, 실패 건수, 소요 시간 |
| 리소스 경로 | API 경로, 스토리지 객체 키(`raw/{videoId}/original.mp4`) |

### 로컬 환경 예외

로컬 개발 환경(`contentria.member.mail.mode=log`)에서는 메일을 실제로 발송하지 않고 인증 코드 및 링크 토큰을 콘솔에 `WARN` 레벨로 기록합니다. 이는 실제 사용자 데이터가 없는 로컬 개발 전용 설정이며, 운영 환경에서는 비활성화합니다.

## 메시지 형식

### 작성 원칙

- **영문 한 줄 작성**: 정규식 파싱과 로그 수집기의 라인 분리를 방지하기 위해 영문 단일 행으로 작성합니다.
- **사건 중심 구성**: 호출 주체가 아닌 발생한 이벤트명으로 시작하고, 주요 식별자를 자리표시자에 배치합니다.
- **후속 처리 명시**: 재시도 여부나 다음 실행 계획을 함께 적어 운영자가 즉각 조치 필요 여부를 판단할 수 있도록 합니다.

```kotlin
// 올바른 형식
log.warn("Video queue pull failed; trying again on the next tick", e)
log.warn("Image {} not cleaned up; its record stays for the next run", id, e)
log.info("Image cleanup completed: removed={}, failed={}", report.removed, report.failed)

// 잘못된 형식
log.info("Success") // 맥락 부재
log.info("User {} created post", email) // 개인정보 포함
log.info("Token refreshed: {}", token) // 민감정보 노출
```

## 계층별 로깅 지침

| 계층 | 권장 레벨 | 로깅 지침 |
|---|---|---|
| 웹 어댑터 | DEBUG (또는 생략) | 요청 본문은 기록하지 않습니다. 예외는 전역 예외 처리기가 응답으로 변환합니다. |
| 애플리케이션 서비스 | INFO / DEBUG | 비즈니스 결과는 INFO, 내부 처리 단계는 DEBUG로 기록합니다. 처리를 계속 진행하는 장애만 WARN으로 기록합니다. |
| 외부 연동 어댑터 | WARN / DEBUG | 정상 호출은 DEBUG, 외부 서비스 장애는 식별자와 함께 WARN으로 기록합니다. |
| 배치 및 큐 워커 | INFO / WARN | 배치 요약 결과는 INFO, 개별 항목 실패는 식별자 및 후속 처리와 함께 WARN으로 기록합니다. |

요청 단위로 일괄 기록하는 전역 AOP 로깅은 로그 저장소 낭비 및 운영 노이즈 방지를 위해 사용하지 않습니다.
