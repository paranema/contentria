# 분석 도메인 규칙

독자의 방문을 집계하고 일별 통계를 생성하여 블로그 소유자와 독자에게 제공하는 비즈니스 규칙을 정의합니다.

## 도메인 개요

### 핵심 용어

분석 컨텍스트에서 방문과 통계 지표를 정의할 때 사용하는 핵심 용어입니다.

| 용어                | 의미                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 방문(`Visit`)       | 독자(비로그인 포함)가 블로그 홈 화면이나 발행된 게시글 상세 화면을 열람한 사건                                                  |
| 방문자 키           | 당일 날짜, 클라이언트 IP, 브라우저 정보(`User-Agent`)로부터 생성한 일방향 식별 값 (날짜가 바뀌면 동일인이라도 다른 키가 부여됨) |
| 조회수(Views)       | 중복 방문 제외 기준을 통과한 유효 방문 횟수                                                                                     |
| 방문자 수(Visitors) | 하루 동안 방문한 서로 다른 방문자 키의 수 (여러 날의 방문자 수 합계는 일별 고유 방문자 수의 단순 합)                            |
| 일별 통계           | 하루 동안 발생한 조회수와 방문자 수를 블로그 전체 단위 및 개별 게시글 단위로 각각 모아 집계한 결과                              |

### 기본 원칙

1. 조회수와 방문자 수를 산정하는 규칙은 분석 컨텍스트가 소유합니다. 단, 대상 블로그와 게시글이 실제로 존재하는지, 공개 상태인지, 누가 소유자인지는 출판 컨텍스트에 확인합니다.
2. 방문자의 실제 IP 원문은 어디에도 저장하지 않으며 오직 방문자 키로만 식별합니다([배경 참고](#방문자-익명-식별-ip-미저장)). 이전 페이지 주소(`Referer`) 역시 호스트(도메인) 부분만 추출해 저장하고 상세 경로와 쿼리스트링은 버립니다.
3. 개별 방문 기록 원본은 외부에 공개하지 않으며 통계 집계 용도로만 사용한 뒤 보관 기한이 지나면 삭제합니다([배경 참고](#원본-방문-기록-보관-기한-90일)).
4. 블로그 대시보드 통계는 해당 블로그의 소유자만 조회할 수 있고, 개별 게시글의 누적 조회수는 누구나 조회할 수 있습니다.

### 정책 기준값

방문 인정, 원본 보관 및 대시보드 통계 산출에 적용하는 기준 수치입니다.

| 항목                    | 기준값                                                                                               |
| ----------------------- | ---------------------------------------------------------------------------------------------------- |
| 하루의 기준             | 한국 표준시(`Asia/Seoul`) 자정(`00:00`)부터 다음 날 자정 전까지                                      |
| 중복 방문 제외 시간     | 동일한 방문자 키가 같은 블로그 홈이나 같은 게시글을 **30분 이내**에 다시 열람한 경우는 집계하지 않음 |
| 원본 방문 기록 보관     | 방문 시각으로부터 **90일** 보관 후 삭제                                                              |
| 대시보드 방문 추이 기간 | 최근 **2주(`2weeks`)**, **30일(`30days`)**, **90일(`90days`)**                                       |
| 대시보드 인기 글        | 최근 **30일간**(오늘 포함) 조회수가 가장 높은 게시글 **상위 5개**                                    |

## 비즈니스 흐름

독자의 열람이 발생했을 때부터 통계 지표로 조회되기까지의 과정을 **방문 기록 수집(흐름 1) → 일별 통계 집계(흐름 2) → 통계 조회(흐름 3, 4)** 순서로 정의합니다. 각 흐름의 조건 표는 위에서부터 순서대로 평가하여 **처음 일치하는 조건**에서 처리를 멈추며, `담당 계층`의 `도메인`은 도메인 모델이 보장하는 불변식을, `앱`은 응용 서비스가 조율하는 애플리케이션 정책을 뜻합니다([02-implementation.md](02-implementation.md) 참고).

### 흐름 1. 방문 기록 수집

독자가 블로그 홈이나 게시글 상세 화면을 열람할 때 방문을 기록합니다. 아래 조건 1~4에 걸려 무시된 요청이더라도 클라이언트에는 정상 기록된 것과 동일한 성공 응답(`204`)을 반환합니다. 클라이언트가 별도로 취할 후속 조치가 없고 어느 조건에 의해 제외되었는지 외부에 노출할 이유도 없기 때문입니다.

| #   | 조건                                                                            | 처리 내용                                                         | 담당 계층 |
| --- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------- | --------- |
| 1   | 대상 블로그가 존재하지 않음                                                     | 기록하지 않고 무시합니다.                                         | 앱        |
| 2   | 게시글 방문인데 해당 글이 없거나, 해당 블로그 소속이 아니거나, 발행 상태가 아님 | 기록하지 않고 무시합니다.                                         | 앱        |
| 3   | 로그인한 방문자가 해당 블로그의 소유자 본인임                                   | 기록하지 않고 무시합니다 ([배경 참고](#블로그-소유자-방문-제외)). | 앱        |
| 4   | 동일한 방문자 키가 같은 블로그 홈 또는 같은 게시글을 30분 이내에 이미 방문함    | 기록하지 않고 무시합니다.                                         | 앱        |
| 5   | 위 조건에 모두 해당하지 않음                                                    | 방문자 키와 유입 도메인을 정규화하여 방문을 기록합니다.           | 도메인    |

### 흐름 2. 일별 통계 집계

정기 배치가 매일 실행되어 마감된 날짜의 방문 기록을 일별 통계로 합산하고 오래된 원본을 정리합니다.

| #   | 처리 단계                                                                                                                                | 담당 계층 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 1   | 이미 종료된 날짜별로 원본 방문 기록을 모아 블로그 전체 단위 및 개별 게시글 단위의 조회수와 방문자 수를 계산합니다.                       | 앱        |
| 2   | 계산된 값으로 해당 날짜의 일별 통계를 덮어씁니다. 동일한 날짜를 여러 번 다시 집계해도 결과는 같습니다.                                   | 앱        |
| 3   | 실행할 때마다 <strong>최근 3일 치(어제, 그제, 3일 전)</strong>를 매번 다시 집계하여, 하루 집계가 누락되더라도 다음 날 자동으로 메웁니다. | 앱        |
| 4   | 방문 시각으로부터 90일이 지난 원본 방문 기록을 삭제합니다.                                                                               | 앱        |

### 흐름 3. 블로그 대시보드 통계 조회

블로그 소유자가 자신의 블로그 대시보드를 열람할 때 통계를 조회합니다.

| #   | 조건                                            | 처리 내용                                                 | 담당 계층 |
| --- | ----------------------------------------------- | --------------------------------------------------------- | --------- |
| 1   | 블로그가 존재하지 않거나 요청자의 블로그가 아님 | 존재하지 않는 블로그와 동일한 응답(`404`)으로 거부합니다. | 앱        |
| 2   | 요청자 본인이 소유한 블로그임                   | 아래 표의 대시보드 지표를 조합해 반환합니다.              | 앱        |

분석 컨텍스트는 아래 표의 순수 트래픽 수치만 산출합니다. 블로그 소유권 확인과 출판 컨텍스트의 정보(인기 글의 제목·슬러그 결합 및 삭제된 글 제외, 현재 발행 게시글 총수 표시)를 합쳐 대시보드 화면 응답을 완성하는 작업은 화면 조합 계층에서 수행합니다([02-implementation.md](02-implementation.md#흐름-34-통계-조회) 참고).

| 대시보드 지표                | 산출 방식                                                                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 오늘 조회수 / 오늘 방문자 수 | 당일 원본 방문 기록에서 실시간으로 집계합니다 ([배경 참고](#당일-실시간-집계과거-일별-통계-분리)).                                                                  |
| 어제 조회수 / 어제 방문자 수 | 어제 날짜의 일별 통계 값을 조회합니다 (집계 실행 전이면 `0`).                                                                                                       |
| 누적 조회수 / 누적 방문자 수 | 과거 모든 일별 통계의 합계에 오늘 실시간 집계치를 더합니다.                                                                                                         |
| 일별 방문 추이               | 선택한 기간(2주·30일·90일)의 날짜별 조회수와 방문자 수 목록입니다. 과거 날짜는 일별 통계에서, 오늘은 원본 방문 기록에서 가져오며 방문이 없던 날은 `0`으로 채웁니다. |
| 인기 글 (Top 5)              | 최근 30일간(오늘 포함) 게시글별 조회수 합계가 높은 순서대로 최대 5개를 선정합니다.                                                                                  |

### 흐름 4. 게시글별 누적 조회수 조회

게시글 목록이나 상세 화면에서 각 게시글의 누적 조회수를 표시할 때 사용합니다.

| 조회 대상               | 산출 방식 및 접근 권한                                                                                            | 담당 계층 |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------- | --------- |
| 개별 게시글 누적 조회수 | 과거 모든 일별 통계의 조회수 합계에 오늘의 실시간 방문 기록 수를 더하여 산출합니다(기록이 없으면 `0`, 전체 공개). | 앱        |

### 외부 상태 변경 시 데이터 처리

출판이나 회원 컨텍스트에서 게시글·블로그·회원의 상태가 변경되었을 때, 분석 컨텍스트가 기존 방문 기록과 통계 데이터를 어떻게 유지하거나 반영하는지 정의합니다.

| 외부 컨텍스트 사건                  | 분석 컨텍스트의 처리 내용                                                                                                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 게시글이 비공개로 전환되거나 삭제됨 | 과거 방문 기록과 일별 통계는 그대로 유지하되, 이후 들어오는 방문은 흐름 1-2에서 차단합니다. 삭제된 글은 대시보드 인기 글 목록에서 제외됩니다.                             |
| 블로그가 삭제됨                     | 과거 방문 기록과 일별 통계를 그대로 유지합니다 ([strategic/04-context-map.md](../../strategic/04-context-map.md#삭제된-블로그의-분석-기록-보존) 참고). |
| 회원이 탈퇴함                       | 방문 기록에는 회원 ID가 저장되지 않으므로 별도 처리 없이 그대로 유지합니다.                                                                                               |

## 정책 결정 배경

### 블로그 소유자 방문 제외

블로그 소유자는 글을 작성하고 다듬는 과정에서 자신의 블로그와 게시글을 반복해서 열어 봅니다. 소유자 본인의 열람까지 조회수에 포함하면 실제 독자 유입 규모를 파악하기 어려워지므로, 로그인한 소유자 본인의 방문은 집계에서 제외합니다.

이때 "누가 블로그 소유자인가"는 출판 컨텍스트가 가진 사실 정보이므로 출판에 조회하고, "소유자의 방문을 집계에서 제외한다"는 규칙 자체는 분석 컨텍스트가 판단합니다.

### 방문자 익명 식별 (IP 미저장)

클라이언트 IP 주소는 개인정보에 해당합니다. 통계 집계에 필요한 것은 방문자의 실제 IP가 아니라 "오늘 같은 글을 다시 열람한 동일인인가"를 구별하는 식별성뿐이므로, 서버 비밀 키를 결합한 일방향 해시 값만 저장합니다.

특히 해시 입력에 **당일 날짜**를 함께 결합하여 자정이 지나면 동일한 사용자라도 완전히 다른 방문자 키가 생성되도록 설계했습니다. 이를 통해 여러 날에 걸쳐 특정 사용자의 방문 궤적을 추적할 수 없게 하면서도 하루 단위의 고유 방문자 수(UV)는 정확히 집계할 수 있습니다(자정을 사이에 둔 30분 이내 재방문이 1회 더 집계될 수 있으나 발생 빈도와 영향이 미미합니다).

### 원본 방문 기록 보관 기한 (90일)

누적 수치와 일별 추이는 모두 가벼운 일별 통계로 조회할 수 있습니다. 무거운 원본 방문 기록은 집계를 재실행하거나 최근 30일 인기 글을 계산하는 용도로만 필요하므로 90일만 보관하고 삭제합니다.

### 당일 실시간 집계·과거 일별 통계 분리

당일 통계를 다음 날 새벽 집계가 끝날 때까지 보여주지 않으면 작성자가 방금 발행한 글의 실시간 반응을 확인할 수 없습니다. 하루 치 원본 방문 기록은 실시간으로 합산해도 부담이 작으므로 오늘 지표는 원본 기록에서 즉시 계산하고, 이미 마감된 과거 날짜는 사전 집계된 일별 통계를 읽어 빠르게 응답합니다.

## 보류 항목

현재 단계에서는 구현하지 않고 제품 요구사항이나 운영 지표가 구체화될 때 도입할 항목입니다.

| 항목                                | 보류 사유                                                                                                                                                                                |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 플랫폼 전체 관리자 대시보드         | 관리자 기능이 구체화될 때 추가합니다.                                                                                                                                                    |
| 유입 도메인(`referrer`)별 통계 화면 | 도메인 데이터는 방문 기록에 수집하고 있으며, 대시보드 화면 요구사항이 정해질 때 집계 쿼리를 추가합니다.                                                                                  |
| 크롤러·봇 트래픽 필터링             | `User-Agent` 기반 봇 제외 기준이 필요하며, 비정상 트래픽으로 인한 지표 왜곡이 관찰될 때 도입합니다.                                                                                      |
| 조회수 순 게시글 목록 정렬          | 출판 컨텍스트의 목록 페이징과 결합해야 하므로 실제 요구사항과 성능 측정 후 도입 여부를 결정합니다 ([strategic/04-context-map.md](../../strategic/04-context-map.md)의 "조회 조합" 참고). |
