# 분석 규칙

독자의 방문을 세고, 하루 단위로 모아, 블로그 소유자에게 보여주는 규칙이다.

각 흐름은 위에서부터 **처음 걸리는 줄**에서 멈춘다.
`계층` 열이 `도메인`인 줄이 도메인 불변식이고, `앱`인 줄이 애플리케이션 정책이다.
분류 기준은 [02-implementation.md](02-implementation.md)에 있다.

## 전제

1. 방문은 독자가 블로그 홈이나 발행된 글을 연 것이다. 화면이 열 때마다 알린다. 로그인하지 않은 독자도 센다.
2. **조회수와 방문자 수를 세는 규칙은 분석의 것이다.** 블로그와 글이 있는지, 공개인지, 누가 소유자인지는 출판에 묻는다.
3. 방문자는 IP와 브라우저 정보에서 만든 **방문자 키**로만 구별한다. IP 원문은 남기지 않는다([왜](#ip를-남기지-않는다)).
4. 방문 기록의 원본은 아무도 보지 않는다. 숫자로만 쓰고, 90일이 지나면 지운다.
5. 블로그의 통계는 그 블로그의 소유자만 본다.

## 처음 정하는 값

| 항목 | 값 |
|---|---|
| 하루 | 한국 시각 자정부터 다음 자정 전까지 |
| 중복 제외 | 같은 방문자가 같은 블로그 홈이나 같은 글을 30분 안에 다시 연 것은 세지 않는다 |
| 방문자 키 | 그날의 날짜, IP, 브라우저 정보(User-Agent)를 비밀 키로 섞은 값. 날이 바뀌면 같은 사람도 다른 키가 된다 |
| 유입 경로 | 이전 페이지 주소(Referer)의 도메인만 남긴다. 경로와 검색어는 남기지 않는다 |
| 방문 기록 보관 | 90일 |
| 방문 추이 | 최근 2주, 30일, 90일 |
| 인기 글 | 최근 30일의 조회수가 많은 순으로 5개 |

## 용어

| 용어 | 뜻 |
|---|---|
| 조회수 | 중복 제외를 거친 방문의 수 |
| 방문자 수 | 하루 동안 서로 다른 방문자 키의 수. 여러 날의 방문자 수는 날마다의 수를 더한 것이다 |
| 일별 통계 | 하루의 조회수와 방문자 수를 블로그 전체와 글마다 모은 것 |

## 흐름 1. 방문 기록

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 블로그가 없음 | 버린다 | 앱 |
| 2 | 글을 열었는데, 그 글이 없거나 그 블로그의 글이 아니거나 발행 상태가 아님 | 버린다 | 앱 |
| 3 | 로그인한 독자가 그 블로그의 소유자 | 버린다([왜](#소유자의-방문은-세지-않는다)) | 앱 |
| 4 | 같은 방문자 키가 같은 블로그 홈이나 같은 글을 30분 안에 기록함 | 버린다 | 앱 |
| 5 | 그 외 | 기록한다 | 도메인 |

버린 방문도 화면에는 성공으로 답한다. 화면이 할 일이 없고, 어느 조건에 걸렸는지 알려줄 이유도 없다.

## 흐름 2. 일별 집계

시스템이 매일 한다.

| # | 처리 |
|---|---|
| 1 | 끝난 날마다 방문 기록을 블로그 전체와 글마다 모아 조회수와 방문자 수를 센다 |
| 2 | 그날의 일별 통계를 새 값으로 바꾼다. 같은 날을 다시 집계해도 결과가 같다 |
| 3 | 최근 3일을 매번 다시 집계한다. 하루를 놓쳐도 다음 실행이 채운다 |
| 4 | 90일이 지난 방문 기록을 지운다 |

## 흐름 3. 블로그 대시보드

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 블로그가 없거나 내 블로그가 아님 | 거부. 없는 블로그와 같은 응답이다 | 앱 |
| 2 | 그 외 | 아래 숫자를 보여준다 | 앱 |

| 숫자 | 계산 |
|---|---|
| 오늘 조회수, 오늘 방문자 수 | 오늘의 방문 기록에서 바로 센다 |
| 어제 조회수, 어제 방문자 수 | 어제의 일별 통계 |
| 누적 조회수, 누적 방문자 수 | 모든 일별 통계의 합에 오늘을 더한다 |
| 방문 추이 | 기간의 날마다 조회수와 방문자 수. 오늘은 방문 기록에서, 지난날은 일별 통계에서. 방문이 없던 날은 0 |
| 인기 글 | 최근 30일 글마다의 조회수 합(오늘 포함)이 많은 순으로 5개. 제목과 주소를 함께 보여준다. 그사이 지워진 글은 빠진다 |
| 발행한 글 수 | 출판이 센다 |

어제가 아직 집계되지 않았으면(집계가 돌기 전) 어제는 0이다.

## 흐름 4. 글의 조회수

글 목록과 상세가 글마다의 누적 조회수를 보여줄 수 있다. 누구나 본다. 모든 일별 통계의 합에 오늘을 더한다.

## 다른 컨텍스트의 일로 생기는 것

| 일 | 분석에서 |
|---|---|
| 글이 비공개가 되거나 지워짐 | 지난 방문과 통계를 그대로 둔다. 새 방문은 흐름 1의 2번에서 버린다. 지워진 글은 대시보드의 인기 글에서 빠진다 |
| 블로그가 지워짐 | 그대로 둔다([strategic/04-context-map.md](../../strategic/04-context-map.md)의 "블로그가 삭제되어도 분석 기록을 남기는 이유") |
| 회원이 탈퇴함 | 그대로 둔다. 방문 기록에는 회원이 남지 않는다 |

## 왜 이렇게 정했나

### 소유자의 방문은 세지 않는다

블로거는 글을 쓰고 고치며 자기 글을 수없이 연다. 그것을 세면 독자가 얼마나 왔는지 알 수 없다. 레거시와 다른 블로그 서비스도 그렇게 한다.
누가 소유자인지는 출판의 사실이므로 출판에 묻는다. 세는 규칙은 분석의 것이므로 분석이 판단한다.

### IP를 남기지 않는다

IP는 개인정보다. 필요한 것은 "같은 사람인가"뿐이므로, 비밀 키로 섞은 값만 남긴다. 키를 모르면 값에서 IP를 되찾을 수 없다.
날짜를 함께 섞어 하루가 지나면 같은 사람도 다른 키가 되게 한다. 여러 날에 걸쳐 한 사람을 따라갈 수 없다. 방문자 수는 하루 단위로만 세므로 잃는 것이 없다.
자정을 넘기는 30분 안의 재방문은 다른 키가 되어 한 번 더 센다. 드물고 영향이 작다.

### 원본은 90일만 둔다

누적과 추이는 일별 통계로 본다. 원본은 집계를 다시 돌리거나 새 숫자를 만들 때만 필요하다. 90일은 그 여유다.

### 오늘은 바로 세고, 지난날은 모아 둔 것을 쓴다

오늘의 숫자를 다음 날 집계까지 기다리게 하면, 방금 쓴 글의 반응을 볼 수 없다. 오늘 하루치 방문 기록은 바로 세어도 가볍다.
지난날은 매번 원본을 세지 않고 일별 통계를 쓴다. 원본은 90일 뒤 지워지기도 한다.

## 레거시와 다른 점

| 레거시 | 여기서 |
|---|---|
| IP, User-Agent, Referer 원문을 저장한다 | 방문자 키와 유입 도메인만 저장한다 |
| 방문자는 IP로만 구별한다 | IP와 브라우저 정보로 구별한다. 같은 IP 뒤의 여러 사람이 덜 묶인다 |
| 블로그는 확인하지만 글이 그 블로그의 공개 글인지는 확인하지 않는다 | 둘 다 출판에 확인한다 |
| 방문 기록을 지우지 않는다 | 90일 뒤 지운다 |
| 일별 집계는 어제 하루만 한다 | 최근 3일을 매번 다시 집계한다 |
| 인기 글 쿼리가 출판의 글 테이블을 직접 JOIN한다 | 분석은 글 ID와 조회수만 주고, 제목은 대시보드 조합이 출판에서 받는다 |
| 대시보드가 요약, 추이, 인기 글을 따로 요청한다 | 한 요청으로 받는다 |

## 보류

| 항목 | 사유 |
|---|---|
| 관리자 대시보드(플랫폼 전체 통계) | 관리자 기능을 만들 때 정한다 |
| 유입 경로 통계 | 도메인을 남겨 두고, 화면이 필요해지면 만든다 |
| 봇 거르기 | User-Agent로 거를 수 있지만 기준이 필요하다. 숫자가 눈에 띄게 부풀면 정한다 |
| 조회수 순 정렬(글 목록) | 출판의 저장소 안에서 정렬해야 한다. 측정 전에 도입하지 않는다([strategic/04-context-map.md](../../strategic/04-context-map.md)의 "조회 조합") |
