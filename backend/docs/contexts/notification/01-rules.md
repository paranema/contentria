# 알림 도메인 규칙

다른 컨텍스트에서 일어난 사건을 회원에게 알리는 비즈니스 규칙을 정의합니다.

## 전제 조건

1. 알림은 다른 컨텍스트에서 이미 발생한 사건의 기록이며, 알림 컨텍스트가 스스로 알림 계기를 만들어내지 않습니다.
2. 모든 알림은 웹 서비스 내의 **알림함(In-app Notification)**으로만 전달합니다. 이메일이나 실시간 푸시 알림은 사용하지 않으며, 프론트엔드가 읽지 않은 알림 수를 주기적으로 조회합니다.
3. 알림 컨텍스트는 회원, 게시글, 블로그, 댓글을 각각의 ID로만 저장합니다. 게시글 제목이나 작성자 표시 이름은 화면 조합 계층에서 결합합니다.
4. **본인이 한 행동은 본인에게 알리지 않습니다.**
5. 알림은 수신자 본인만 조회하고 읽음 처리할 수 있습니다.
6. 회원 컨텍스트에서 발송하는 보안·인증 메일(가입 인증 코드, 비밀번호 재설정 링크 등)은 알림 컨텍스트의 대상이 아니며 회원 컨텍스트가 직접 발송합니다([이유 참고](#회원의-안내-메일은-회원이-보낸다)).

## 기본 제약 수치

| 항목           | 기준값                                                      |
| -------------- | ----------------------------------------------------------- |
| 알림 목록 조회 | 최신순으로 페이지당 20개씩 조회                             |
| 알림 보존 기간 | 생성 후 90일 (읽음 여부와 무관하게 90일이 지나면 자동 삭제) |

## 알림 종류 (`NotificationType`)

| 종류           | 발생 계기                                | 수신 대상          | 알림에 담기는 참조 ID                  |
| -------------- | ---------------------------------------- | ------------------ | -------------------------------------- |
| 새 글 발행     | 구독 중인 블로그에 게시글이 최초 발행됨  | 해당 블로그 구독자 | 게시글 ID, 블로그 ID                   |
| 내 글의 댓글   | 내 블로그의 게시글에 댓글이나 답글이 달림| 블로그 소유자      | 게시글 ID, 블로그 ID, 댓글 ID, 작성자 ID|
| 내 댓글의 답글 | 내가 작성한 댓글에 답글이 달림           | 부모 댓글 작성자   | 게시글 ID, 블로그 ID, 답글 ID, 작성자 ID|

## 주요 비즈니스 흐름

알림 컨텍스트의 동작은 외부 도메인 이벤트를 받아 알림을 기록하는 **새 글 알림 생성(흐름 1) 및 댓글·답글 알림 생성(흐름 2)**과, 수신자가 알림을 확인하는 **알림함 조회 및 읽음 처리(흐름 3)**의 세 가지 흐름으로 구성됩니다.

- 알림 생성 흐름(흐름 1, 2)은 조건 표의 모든 행을 평가해 해당하는 알림을 생성하며, 알림함 조작 흐름(흐름 3)은 **처음 일치하는 조건**에서 처리를 멈춥니다.
- `담당 계층` 열이 `도메인`으로 표기된 항목은 도메인 모델이 보장하는 불변식이고, `앱`으로 표기된 항목은 응용 서비스가 조율하는 애플리케이션 정책입니다.
  - 분류 기준은 [02-implementation.md](02-implementation.md) 참고

### 흐름 1. 새 글 알림 생성

게시글이 최초로 발행될 때(`PostPublished`) 실행됩니다. 비공개로 전환했던 글을 다시 공개하는 경우에는 발생하지 않습니다.

| # | 조건                                 | 처리 내용                                                                       | 담당 계층   |
| - | ------------------------------------ | ------------------------------------------------------------------------------- | ----------- |
| 1 | 해당 블로그에 구독자가 한 명도 없음  | 알림을 생성하지 않고 종료합니다.                                                | 앱          |
| 2 | 구독자가 존재함                      | 이벤트를 처리하는 시점의 각 구독자 앞으로 '새 글' 알림을 1건씩 생성합니다.      | 앱 + 도메인 |

- 블로그 소유자는 자신의 블로그를 구독할 수 없으므로 본인 글 발행 알림을 받지 않습니다.
- 게시글이 발행된 이후에 새로 구독한 회원은 과거 발행 글의 알림을 받지 않으며, 반대로 알림이 생성된 뒤 구독을 해지하더라도 이미 만들어진 알림은 그대로 남습니다.

### 흐름 2. 댓글 및 답글 알림 생성

댓글이나 답글이 작성될 때(`CommentAdded`) 실행됩니다. 아래 두 규칙을 모두 적용하되, **동일한 수신자에게는 하나의 댓글 사건당 최대 1개의 알림만** 생성합니다.

| # | 조건                                                                           | 처리 내용                                                      | 담당 계층   |
| - | ------------------------------------------------------------------------------ | -------------------------------------------------------------- | ----------- |
| 1 | 답글이 작성되었고, 부모 댓글 작성자가 답글 작성자 본인이 아님                  | 부모 댓글 작성자에게 **'내 댓글의 답글'** 알림을 생성합니다.   | 앱 + 도메인 |
| 2 | 댓글·답글 작성자가 블로그 소유자가 아니고, 1번 규칙에서 블로그 소유자가 이미 알림을 받지 않음| 블로그 소유자에게 **'내 글의 댓글'** 알림을 생성합니다. | 앱 + 도메인 |

#### 시나리오별 수신자 예시 (`B`의 블로그 게시글 기준)

| 작성 시나리오                                   | 생성되는 알림 수신자 및 종류                            |
| ----------------------------------------------- | ------------------------------------------------------- |
| 독자 `A`가 `B`의 게시글에 댓글 작성             | `B`: 내 글의 댓글                                       |
| 블로그 소유자 `B`가 자신의 게시글에 댓글 작성   | 없음 (본인 행동 제외)                                   |
| 독자 `C`가 `A`의 댓글에 답글 작성               | `A`: 내 댓글의 답글, `B`: 내 글의 댓글                  |
| 블로그 소유자 `B`가 `A`의 댓글에 답글 작성      | `A`: 내 댓글의 답글                                     |
| 독자 `C`가 블로그 소유자 `B`의 댓글에 답글 작성 | `B`: 내 댓글의 답글 (중복 방지로 1건만 생성)            |
| 독자 `A`가 자신이 쓴 댓글에 스스로 답글 작성    | `B`: 내 글의 댓글 (`A` 본인은 제외)                     |

### 흐름 3. 알림함 조회 및 읽음 처리

| # | 요청 종류   | 조건                                     | 처리 내용                                                          | 담당 계층 |
| - | ----------- | ---------------------------------------- | ------------------------------------------------------------------ | --------- |
| 1 | 알림 목록   | -                                        | 내 알림 목록을 최신순으로 읽음 여부와 함께 반환합니다.             | 앱        |
| 2 | 안 읽은 수  | -                                        | 내 알림 중 아직 읽지 않은 알림의 개수를 반환합니다.                | 앱        |
| 3 | 단건 읽음   | 내 알림이 아니거나 존재하지 않는 알림임  | 존재하지 않는 알림과 동일한 응답(`404`)으로 거부합니다.            | 앱        |
| 4 | 단건 읽음   | 이미 읽음 처리된 알림임                  | 최초 읽은 시각을 그대로 유지하고 성공(`204`)으로 응답합니다.       | 도메인    |
| 5 | 단건 읽음   | 아직 읽지 않은 내 알림임                 | 읽음 상태로 표시하고 현재 시각을 기록합니다.                       | 도메인    |
| 6 | 전체 읽음   | -                                        | 요청 시점까지 쌓인 내 미열람 알림을 모두 읽음 상태로 표시합니다.   | 앱        |

- 사용자가 개별 알림을 수동으로 삭제하는 기능은 제공하지 않으며, 생성 후 90일이 지나면 자동으로 삭제됩니다.

## 외부 컨텍스트 상태 변경에 따른 데이터 처리

출판, 상호작용, 회원 컨텍스트에서 게시글·댓글·구독·계정 상태가 변경되었을 때, 이미 생성된 알림 레코드를 어떻게 처리하는지 정의합니다.

| 외부 컨텍스트 사건               | 알림 컨텍스트의 처리 내용                                                                            |
| -------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 게시글이 삭제되거나 비공개 전환됨| 알림 레코드는 그대로 두며, 화면 조합 시 게시글 정보를 조회하지 못하면 해당 알림을 노출하지 않습니다. |
| 댓글이 삭제됨                    | 알림 레코드는 그대로 두며, 클릭 시 해당 게시글로 안내합니다.                                         |
| 블로그 구독을 해지함             | 해지 이전에 이미 생성된 알림은 그대로 유지합니다.                                                    |
| 수신자가 탈퇴하거나 정지됨       | 알림은 정상 생성·유지되나 해당 계정이 로그인할 수 없으므로 조회되지 않으며 90일 뒤 자동 삭제됩니다.  |
| 댓글 작성자가 탈퇴함             | 알림은 그대로 유지하며, 화면 조합 시 회원 컨텍스트의 탈퇴 프로필 표시로 나타납니다.                  |

## 결정과 이유

### 받은 시점의 구독자마다 알림을 만든다

새 글이 발행될 때 구독자 수만큼 알림 행을 개별 생성(Fan-out on Write)하면, 수신자별 읽음 상태를 각 행에 단순하게 기록할 수 있고 알림함을 열 때 내 알림 행만 빠르게 조회할 수 있습니다. 구독자가 많은 블로그에서는 게시글 하나당 여러 행이 생성되지만, 90일 보존 기한이 전체 테이블 크기의 상한선 역할을 합니다.

반대로 알림함을 열 때마다 구독 중인 블로그의 새 글을 실시간으로 모아 보여주는 방식(Fan-out on Read)은 저장 공간은 적게 들지만, 조회할 때마다 상호작용·출판 컨텍스트를 함께 읽어야 하고 읽음 여부를 별도 테이블로 관리해야 하므로 채택하지 않았습니다.

### 자기가 한 일은 자기에게 알리지 않는다

자신의 글에 직접 댓글을 남기거나 자신의 댓글에 답글을 추가한 사실은 작성자 본인이 이미 알고 있으므로, 알림함에 쌓여 정작 다른 독자가 남긴 알림을 가리지 않도록 제외합니다.

### 알림은 ID만 담는다

알림 레코드에 생성 당시의 게시글 제목이나 작성자 닉네임을 문자열로 복사해 두면, 이후 게시글 제목이 수정되거나 회원이 표시 이름을 바꾸더라도 옛날 이름이 노출되고 비공개 전환·삭제된 글의 제목까지 알림함에 남게 됩니다.

참조 ID만 저장하고 화면에 표시할 때 현재 제목과 프로필을 조합하면 항상 최신 정보가 노출되며, 비공개로 전환되거나 삭제된 글의 알림도 자연스럽게 걸러낼 수 있습니다. 또한 출판·상호작용 컨텍스트가 발행하는 이벤트 페이로드에도 최소한의 식별자만 담는 원칙([strategic/04-context-map.md](../../strategic/04-context-map.md) 참고)을 지킬 수 있습니다.

### 회원의 안내 메일은 회원이 보낸다

회원가입 인증 코드나 비밀번호 재설정 링크 메일은 회원 인증 플로우의 즉각적인 일부입니다. 만약 이를 알림 컨텍스트로 넘겨 도메인 이벤트와 Kafka를 거치게 하면 메일 도착이 지연될 뿐 아니라 발송 실패 시 회원 플로우에서 즉시 대응할 수 없습니다. 따라서 알림 컨텍스트는 타 컨텍스트에서 이미 완결된 도메인 사건만 다룹니다.

## 보류

| 항목                                            | 보류 사유                                                                  |
| ----------------------------------------------- | -------------------------------------------------------------------------- |
| 좋아요 및 새 구독자 알림 (`PostLiked`, `BlogSubscribed`)| 인기 글에 반응이 몰릴 때 알림함이 도배되지 않도록 알림 묶음 규칙과 함께 도입합니다. |
| 다건 알림 묶기 ("외 3명이 댓글을 남겼습니다")   | 실제 알림 발생량을 운영하며 필요성이 확인될 때 추가합니다.                 |
| 이메일 알림, 웹 푸시(SSE/WebSocket), 수신 설정  | 인앱 알림함으로 먼저 운영한 뒤 확장합니다.                                 |
| 알림 수동 삭제                                  | 90일 자동 삭제 정책으로 충분한지 운영 후 판단합니다.                       |
