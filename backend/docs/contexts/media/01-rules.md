# 미디어 도메인 규칙

게시글 본문에 삽입되는 이미지와 게시글에 첨부되는 영상을 업로드해 검증·변환하고, 게시글과 연결하며, 사용되지 않는 파일을 정리하는 비즈니스 규칙을 정의합니다.

## 도메인 개요

### 핵심 용어

미디어 컨텍스트에서 관리하는 두 종류의 미디어 자산(`Media`, `Video`)과 상태 모델입니다.

| 용어 및 상태                   | 의미                                                                                                              |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 본문 이미지 (`Media`)          | 게시글 마크다운 본문 안에 삽입되는 이미지 파일                                                                    |
| 이미지 `업로드 중 (UPLOADING)` | 서명된 업로드 주소를 발급한 초기 상태                                                                             |
| 이미지 `사용 가능 (READY)`     | 스토리지 업로드와 파일 형식 검증을 통과하여 게시글에 연결할 수 있는 상태                                          |
| 첨부 영상 (`Video`)            | 게시글당 최대 1개 첨부할 수 있는 동영상 파일 (백그라운드에서 HLS 스트리밍 형식으로 변환 후 노출)                  |
| 영상 `대기 (PENDING)`          | 업로드 주소를 발급한 상태이며 원본 업로드 완료 및 변환 시작을 기다리는 상태                                       |
| 영상 `변환 중 (PROCESSING)`    | 변환 워커가 작업을 인계받아 HLS 트랜스코딩을 진행 중인 상태                                                       |
| 영상 `완료 (COMPLETED)`        | HLS 스트리밍 파일과 대표 포스터 이미지 생성이 완료되어 독자가 재생할 수 있는 상태                                 |
| 영상 `실패 (FAILED)`           | 유효한 영상 스트림이 아니거나 제한 길이(5분)를 초과했거나 변환 제한 시간을 넘긴 영구 실패 상태                    |
| 미연결 상태                    | 업로드·변환된 이미지나 영상이 현재 어떤 게시글에도 연결되어 있지 않은 상태 (유예 기간 경과 시 정리 배치에서 삭제) |

### 기본 원칙

1. 이미지와 영상은 로그인한 회원이 업로드합니다. 단, 미디어 컨텍스트는 회원 컨텍스트에 계정 상태를 조회하지 않습니다([배경 참고](#회원-계정-상태-미조회-원칙)).
2. 파일 바이트는 브라우저가 오브젝트 스토리지에 직접 업로드하며, 백엔드 서버는 스토리지에 업로드할 수 있는 서명된 임시 주소(Presigned Upload URL)만 발급합니다.
3. **이미지의 공개 주소(URL)는 업로드를 준비할 때 확정되며 이후 바뀌지 않습니다.** 게시글 본문에는 처음 발급받은 주소를 그대로 삽입합니다([배경 참고](#업로드-준비-시점의-이미지-주소-확정)). 반면 영상은 변환이 완료(`COMPLETED`)된 뒤에야 독자에게 스트리밍 주소가 노출됩니다.
4. 미디어 컨텍스트는 게시글 본문을 파싱하지 않습니다. 본문에서 이미지 주소를 추출하는 책임은 출판 컨텍스트에 있으며, 출판 컨텍스트가 추출한 이미지 주소 목록과 첨부 영상 ID를 미디어 컨텍스트에 전달합니다.
5. 공개된 이미지 파일과 변환 완료된 영상 스트림은 누구나 조회할 수 있지만, 업로드 기록과 연결 상태는 업로드한 회원 본인만 다룰 수 있습니다.

### 정책 기준값

이미지와 영상의 업로드 허용 형식, 용량 한도, 변환 사양 및 보존 기한에 적용하는 기준 수치입니다.

| 구분        | 항목                    | 기준값                                                                                                          |
| ----------- | ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| 본문 이미지 | 허용 이미지 형식        | `JPEG`, `PNG`, `WebP`, `GIF`                                                                                    |
| 본문 이미지 | 단일 파일 최대 크기     | **10MB 이하**                                                                                                   |
| 본문 이미지 | 일일 업로드 용량 한도   | 회원당 하루(한국 시각 자정 기준) **100MB 이하** (당일 준비되어 남아 있는 업로드 합산, 검증 실패·삭제 항목 제외) |
| 본문 이미지 | 게시글당 최대 이미지 수 | **20개 이하** — 출판 컨텍스트의 규칙입니다([publishing/01-rules.md](../publishing/01-rules.md) 참고).           |
| 본문 이미지 | 미완료 업로드 보존 기한 | 업로드 준비 후 **24시간** 이내에 완료 처리되지 않으면 삭제                                                      |
| 첨부 영상   | 허용 영상 형식          | `MP4`, `MOV`, `WebM`, `MKV`                                                                                     |
| 첨부 영상   | 단일 파일 최대 크기     | **500MB 이하** (단일 업로드)                                                                                    |
| 첨부 영상   | 최대 재생 길이          | **5분 이하** (변환 단계에서 실제 스트림 길이를 검사)                                                            |
| 첨부 영상   | 변환 출력 사양          | HLS `720p`, `480p` (원본 해상도보다 높은 화질은 생성하지 않음) 및 대표 포스터 이미지 1장                        |
| 첨부 영상   | 장기 변환 타임아웃      | `변환 중(PROCESSING)` 상태로 **2시간**이 경과하면 `실패(FAILED)`로 전환                                         |
| 공통        | 업로드 주소 유효 시간   | 발급 후 **10분**                                                                                                |
| 공통        | 미연결 파일 보존 기한   | 어느 게시글에도 연결되지 않은 상태가 **7일간** 지속되면 스토리지 파일과 기록을 모두 삭제                        |

## 비즈니스 흐름

이미지의 생명주기는 **업로드 준비(흐름 1) → 업로드 완료·검증(흐름 2) → 게시글 연결 동기화·해제(흐름 3, 4) → 직접 삭제·정기 정리(흐름 5, 6)** 순서로 진행되며, 영상의 생명주기는 **업로드 준비(흐름 V1) → 백그라운드 HLS 변환(흐름 V2) → 게시글 연결·독자 재생 조회(흐름 V3, V4) → 정기 정리(흐름 V5)** 순서로 진행됩니다. 각 조건 표는 위에서부터 순서대로 평가하여 **처음 일치하는 조건**에서 처리를 멈추며(흐름 3은 전달된 이미지 주소마다 개별 적용), `검증 계층`(`담당 계층`)의 구분 기준은 [02-implementation.md](02-implementation.md)를 따릅니다.

### 흐름 1. 이미지 업로드 준비

브라우저가 이미지를 업로드하기 전에 서명된 업로드 주소와 영구 공개 주소를 발급받습니다. 발급된 업로드 주소는 준비 요청 시 선언한 파일 형식(`Content-Type`)과 크기(`Content-Length`)로만 업로드할 수 있으며, 다른 형식이나 크기로 전송하면 오브젝트 스토리지가 직접 거부합니다.

| #   | 조건                                                             | 처리 내용                                                                                    | 검증 계층   |
| --- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ----------- |
| 1   | 허용된 이미지 형식이 아님                                        | 요청을 거부합니다.                                                                           | 도메인      |
| 2   | 파일 크기가 0바이트이거나 10MB를 초과함                          | 요청을 거부합니다.                                                                           | 도메인      |
| 3   | 당일 준비한 업로드 총량에 이번 파일 크기를 더하면 100MB를 초과함 | 요청을 거부합니다 (`429 Too Many Requests`).                                                 | 앱          |
| 4   | 위 조건에 모두 해당하지 않음                                     | 업로드 주소(유효 시간 10분)와 영구 이미지 주소를 발급하고 상태를 `업로드 중`으로 기록합니다. | 도메인 + 앱 |

### 흐름 2. 이미지 업로드 완료

브라우저가 스토리지 업로드를 마친 뒤 백엔드에 완료를 알리는 흐름입니다. 프론트엔드 에디터는 이 완료 요청이 성공한 뒤에야 본문에 이미지를 삽입합니다([배경 참고](#업로드-완료-시점의-시그니처-검증메타데이터-제거)).

| #   | 조건                                                      | 처리 내용                                                                                       | 담당 계층   |
| --- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------- |
| 1   | 본인이 준비한 이미지가 아니거나 존재하지 않음             | 존재하지 않는 이미지와 동일한 응답(`404`)으로 거부합니다.                                       | 앱          |
| 2   | 이미 완료 처리된 이미지임                                 | 별도 변경 없이 성공으로 응답합니다 (멱등성 보장).                                               | 도메인      |
| 3   | 오브젝트 스토리지에 파일이 아직 존재하지 않음             | 요청을 거부합니다 (업로드 주소가 아직 유효하면 파일 업로드 후 다시 완료를 요청할 수 있음).      | 앱          |
| 4   | 파일 헤더(시그니처)가 준비 시 선언한 형식과 일치하지 않음 | 요청을 거부하고 스토리지의 파일과 업로드 기록을 즉시 삭제합니다.                                | 도메인 + 앱 |
| 5   | 이미지 형식이 `JPEG`임                                    | 촬영 위치·기기 정보 등 EXIF 메타데이터를 제거한 이미지로 동일 주소에 덮어쓴 뒤 완료 처리합니다. | 앱          |
| 6   | 위 조건에 모두 해당하지 않음                              | 상태를 `사용 가능(READY)`으로 전환합니다 (아직 어떤 게시글에도 연결되지 않은 상태).             | 도메인      |

### 흐름 3. 게시글 이미지 연결 동기화

게시글이 저장(작성·수정)될 때마다 출판 컨텍스트가 본문에 포함된 이미지 주소 목록을 전달하면, 미디어 컨텍스트는 해당 게시글의 이미지 연결 상태를 전달된 목록과 일치시킵니다(멱등성 보장). 기존에 연결되어 있었으나 이번 목록에서 빠진 이미지는 연결을 해제하며, 하나의 이미지는 동일 회원이 작성한 여러 게시글에 동시에 연결될 수 있습니다.

| #   | 조건                                                      | 처리 내용                                                      | 담당 계층 |
| --- | --------------------------------------------------------- | -------------------------------------------------------------- | --------- |
| 1   | 미디어 컨텍스트가 발급한 이미지 주소가 아님 (외부 이미지) | 무시하고 넘어갑니다.                                           | 앱        |
| 2   | 업로드 완료(`READY`) 상태가 아닌 이미지임                 | 연결하지 않습니다.                                             | 도메인    |
| 3   | 게시글 작성자 본인이 업로드한 이미지가 아님               | 연결하지 않습니다 (해당 이미지는 원래 업로더의 소유로 유지).   | 도메인    |
| 4   | 위 조건에 모두 해당하지 않음                              | 해당 게시글과 이미지를 연결합니다 (이미 연결되어 있으면 유지). | 도메인    |

### 흐름 4. 게시글 삭제 시 연결 해제

출판 컨텍스트에서 게시글이 삭제된 뒤 이를 알리면 해당 게시글에 연결되어 있던 모든 이미지와 영상의 연결을 해제합니다. 연결이 모두 해제된 파일은 즉시 삭제하지 않고 정기 정리 배치(흐름 6, 흐름 V5)에서 7일 유예 기간 경과 후 삭제합니다.

### 흐름 5. 이미지 직접 삭제

글 작성·편집 도중 에디터에 넣었다가 지운 이미지를 즉시 정리할 때 사용하며, 직접 호출하지 않더라도 흐름 6의 정기 배치가 7일 뒤 자동으로 정리합니다.

| #   | 조건                                            | 처리 내용                                                               | 담당 계층 |
| --- | ----------------------------------------------- | ----------------------------------------------------------------------- | --------- |
| 1   | 본인이 업로드한 이미지가 아니거나 존재하지 않음 | 존재하지 않는 이미지와 동일한 응답(`404`)으로 거부합니다.               | 앱        |
| 2   | 하나 이상의 게시글에 연결되어 있는 이미지임     | 삭제를 거부합니다 (게시글 본문에서 이미지를 제거해 저장하면 연결 해제). | 도메인    |
| 3   | 위 조건에 모두 해당하지 않음                    | 스토리지의 파일과 업로드 기록을 즉시 삭제합니다.                        | 앱        |

### 흐름 6. 미사용 이미지 정기 정리

정기 배치가 주기적으로 실행되어 고아 파일과 만료된 업로드 기록을 정리합니다. 스토리지 파일 삭제 도중 오류가 발생하면 DB 기록을 지우지 않고 남겨 두어 다음 배치 실행 시 재시도하게 함으로써, DB 기록만 사라지고 스토리지에 영구 고아 파일이 남는 현상을 방지합니다.

| #   | 정리 대상 조건                                                            | 처리 내용                                                | 담당 계층 |
| --- | ------------------------------------------------------------------------- | -------------------------------------------------------- | --------- |
| 1   | `업로드 중(UPLOADING)` 상태로 24시간이 경과함                             | 스토리지 파일(존재하는 경우)과 업로드 기록을 삭제합니다. | 앱        |
| 2   | `사용 가능(READY)` 상태이나 어떤 게시글에도 연결되지 않은 채 7일이 경과함 | 스토리지 파일과 업로드 기록을 삭제합니다.                | 앱        |

### 흐름 V1. 영상 업로드 준비

브라우저가 첨부 영상을 업로드하기 전에 서명된 업로드 주소와 영상 ID를 발급받습니다.

| #   | 조건                                     | 처리 내용                                                                             | 검증 계층   |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------- | ----------- |
| 1   | 허용된 영상 형식이 아님                  | 요청을 거부합니다.                                                                    | 도메인      |
| 2   | 파일 크기가 0바이트이거나 500MB를 초과함 | 요청을 거부합니다.                                                                    | 도메인      |
| 3   | 위 조건에 모두 해당하지 않음             | 업로드 주소(유효 시간 10분)와 영상 ID를 발급하고 상태를 `대기(PENDING)`로 기록합니다. | 도메인 + 앱 |

### 흐름 V2. 영상 백그라운드 변환

오브젝트 스토리지에 원본 영상이 업로드되면 스토리지 이벤트가 큐를 통해 변환 워커에 전달되어 HLS 트랜스코딩을 수행합니다.

| #   | 조건                                                   | 처리 내용                                                                                    | 담당 계층   |
| --- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------- | ----------- |
| 1   | 해당 원본 키에 대응하는 영상 기록이 DB에 없음          | 메시지를 정상 확인(ACK) 처리하고 건너뜁니다.                                                 | 앱          |
| 2   | 이미 `완료(COMPLETED)`되었거나 `실패(FAILED)`한 영상임 | 메시지를 정상 확인(ACK) 처리하고 건너뜁니다 (중복 메시지 멱등 처리).                         | 도메인      |
| 3   | 유효한 영상 스트림이 없거나 길이가 5분을 초과함        | 상태를 `실패(FAILED)`로 전환하고 메시지를 확인(ACK) 처리합니다 (재시도하지 않음).            | 앱 → 도메인 |
| 4   | 네트워크·스토리지 등 일시적 오류로 변환에 실패함       | 메시지를 확인(ACK)하지 않고 두어 큐가 재전달하게 합니다 (3회 실패 시 DLQ로 이동).            | 앱          |
| 5   | 위 조건에 모두 해당하지 않음                           | 상태를 `변환 중`으로 바꾸고 HLS·포스터를 생성한 뒤 `완료`로 전환하고 원본 파일을 삭제합니다. | 앱 → 도메인 |

### 흐름 V3. 게시글 영상 연결 동기화

게시글을 저장할 때마다 출판 컨텍스트가 해당 게시글에 첨부된 영상 ID(없으면 `null`)를 전달하면, 미디어 컨텍스트는 해당 게시글의 영상 연결 상태를 동기화합니다. 기존에 연결되어 있던 다른 영상은 연결을 해제하며, 이미지와 마찬가지로 하나의 영상을 동일 회원의 여러 게시글에 연결할 수 있습니다.

| #   | 조건                                                    | 처리 내용                                                                             | 담당 계층 |
| --- | ------------------------------------------------------- | ------------------------------------------------------------------------------------- | --------- |
| 1   | 영상이 존재하지 않거나 게시글 작성자가 올린 영상이 아님 | 연결하지 않습니다.                                                                    | 도메인    |
| 2   | 게시글 작성자가 올린 영상임                             | 현재 변환 상태와 무관하게 게시글에 연결합니다 (변환이 완료되면 독자에게 자동 노출됨). | 도메인    |

### 흐름 V4. 독자용 영상 재생 조회

독자가 게시글 상세 화면을 열람할 때 첨부 영상의 현재 상태에 따라 반환하는 정보입니다.

| 영상 상태          | 조회 응답 데이터                                                              |
| ------------------ | ----------------------------------------------------------------------------- |
| `완료 (COMPLETED)` | HLS 마스터 플레이리스트 주소, 포스터 이미지 주소, 재생 시간, 가로·세로 해상도 |
| `대기`, `변환 중`  | 상태 값만 반환 (화면에서는 "영상 변환 중" 안내 표시)                          |
| `실패 (FAILED)`    | 상태 값만 반환 (화면에서는 "영상 처리 실패" 안내 표시)                        |

### 흐름 V5. 미사용·장기 변환 영상 정리

정기 배치가 주기적으로 실행되어 장시간 멈춘 변환 작업과 미연결 영상을 정리합니다.

| #   | 정리 대상 조건                                | 처리 내용                                                                                          | 담당 계층   |
| --- | --------------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------- |
| 1   | `변환 중(PROCESSING)` 상태로 2시간이 경과함   | 큐의 재시도가 모두 끝난 시점이므로 상태를 `실패(FAILED)`로 전환합니다.                             | 앱 → 도메인 |
| 2   | 어떤 게시글에도 연결되지 않은 채 7일이 경과함 | 영상 상태와 무관하게 스토리지의 원본, 변환된 HLS 파일, 포스터 이미지 및 DB 기록을 모두 삭제합니다. | 앱          |

### 외부 상태 변경 시 데이터 처리

출판이나 회원 컨텍스트에서 게시글이나 회원의 상태가 변경되었을 때, 미디어 컨텍스트가 파일 연결과 업로드 기록을 어떻게 처리하는지 정의합니다. 만약 출판 컨텍스트가 게시글 저장을 커밋한 직후 미디어 연결 호출 전에 장애가 발생하더라도, 이후 게시글을 다시 수정·저장하면 정상 연결되며 7일 동안 재저장이 없으면 정기 정리 배치(흐름 6, 흐름 V5)에 의해 정리됩니다([배경 참고](#게시글-저장-커밋-이후의-미디어-연결-동기화)).

| 외부 컨텍스트 사건       | 미디어 컨텍스트의 처리 내용                                                                                                 |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 게시글이 작성·수정됨     | 흐름 3 및 흐름 V3 수행 — 출판 컨텍스트가 저장 트랜잭션 커밋 후 호출하여 이미지·영상 연결을 동기화합니다.                    |
| 게시글이 삭제됨          | 흐름 4 수행 — 출판 컨텍스트가 삭제 트랜잭션 커밋 후 호출하여 이미지·영상 연결을 모두 해제합니다.                            |
| 게시글이 비공개로 전환됨 | 별도 처리 없음 — 비공개 게시글의 이미지·영상 연결도 그대로 유지합니다.                                                      |
| 회원이 탈퇴하거나 정지됨 | 별도 처리 없음 — 정지된 회원은 게시글을 저장할 수 없으므로 새로 올린 파일은 연결되지 못한 채 정기 정리 배치에서 삭제됩니다. |

## 정책 결정 배경

### 업로드 준비 시점의 이미지 주소 확정

과거 구조에서는 이미지를 임시 경로(`tmp/`)에 먼저 업로드한 뒤 게시글을 저장할 때 영구 경로로 복사(승격)하면서 본문 안의 이미지 URL을 치환했습니다. 이로 인해 게시글 저장 트랜잭션이 스토리지 파일 복사 시간을 기다려야 했고, 저장이 실패하더라도 이미 이동된 파일은 되돌릴 수 없었습니다.

업로드 준비 시점에 최종 영구 주소를 미리 확정하면 게시글 저장 시 파일을 이동하거나 본문 URL을 고칠 필요가 없으며, 미디어 컨텍스트는 오직 '어느 게시글과 연결되었는가'만 기록하면 됩니다.

### 업로드 완료 시점의 시그니처 검증·메타데이터 제거

파일 경로 승격 단계가 없으므로 스토리지 업로드가 끝난 직후(`complete`)에 파일 형식을 검증합니다. 프론트엔드 에디터는 완료 요청이 성공한 뒤에야 본문에 이미지를 삽입하므로, 검증에 실패한 파일은 본문에 들어가지 않으며 스토리지에서도 즉시 삭제할 수 있습니다.

브라우저가 요청에 적어 보낸 `Content-Type`만 그대로 신뢰하면 이미지로 위장한 HTML이나 스크립트 파일이 스토리지에 그대로 배포될 수 있으므로 파일의 앞 12바이트(Magic Bytes 시그니처)를 직접 읽어 실제 이미지 형식을 검증합니다. 또한 `JPEG` 파일은 촬영 위치(GPS)나 기기 정보 같은 민감한 EXIF 메타데이터가 포함될 수 있으므로 이미지를 다시 인코딩해 메타데이터를 제거합니다(`PNG`, `WebP`, 그리고 재저장 시 애니메이션이 사라지는 `GIF`는 원본 바이트를 유지합니다 — [design-notes/media-upload-hardening.md](../../design-notes/media-upload-hardening.md) 참고).

### 게시글 저장 커밋 이후의 미디어 연결 동기화

게시글 저장과 미디어 연결은 서로 다른 바운디드 컨텍스트의 로컬 트랜잭션이므로 단일 DB 트랜잭션으로 묶을 수 없습니다.

게시글 저장이 커밋된 이후에 미디어 연결을 호출하면, 설령 연결 호출이 일시적으로 실패하더라도 남는 부작용은 "파일이 아직 연결 표시되지 않았다"는 것뿐입니다. 이는 다음 수정·저장 시 자동으로 맞춰지고 끝내 쓰이지 않으면 7일 뒤 배치에서 정리되므로 복잡한 보상 트랜잭션(롤백 로직)이 필요하지 않습니다. 미연결 파일의 유예 기간을 7일로 넉넉히 둔 이유도 일시적 장애 이후 재저장할 시간적 여유를 확보하기 위함입니다.

### 회원 계정 상태 미조회 원칙

미디어 컨텍스트는 다른 어떤 컨텍스트도 호출하지 않는 순수 하위(Downstream) 컨텍스트입니다([architecture/03-context-integration.md](../../architecture/03-context-integration.md) 참고). 설령 정지된 회원이 파일을 업로드하더라도 출판 컨텍스트에서 게시글 저장이 차단되므로 해당 파일은 어떤 글에도 연결되지 못하고 정기 정리 배치에 의해 삭제됩니다.

## 보류 항목

현재 단계에서는 구현하지 않고 인프라 구성이나 실제 운영 요구사항이 확인될 때 도입할 항목입니다.

| 항목                                                   | 보류 사유                                                                                                                                 |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 업로드 요청 빈도 제한 (Rate Limiting)                  | 도메인 규칙이 아닌 공통 API 요청 필터 관심사이므로 게이트웨이나 웹 필터에서 별도로 적용합니다.                                            |
| CDN 응답 보안 헤더 (`X-Content-Type-Options: nosniff`) | 오브젝트 스토리지 및 CDN 인프라 설정 항목이므로 인프라 구성 단계에서 적용합니다.                                                          |
| 타인의 이미지 URL을 본문에 그대로 복사해 넣은 경우     | 타인 소유 이미지는 연결되지 않으므로 원래 업로더가 자신의 글에서 해당 이미지를 지우면 7일 뒤 깨집니다. 실제 문제가 될 때 정책을 정합니다. |
| 마크다운 본문 내 인라인 HTML `<img>` 태그              | 현재 출판 컨텍스트는 표준 마크다운 이미지 문법만 추출합니다. 에디터가 HTML `<img>`를 생성하지 않으므로 현행 유지합니다.                   |
| 대용량 영상 멀티파트 업로드 (Multipart Upload)         | 현재는 500MB 이하 파일을 단일 요청으로 업로드하며, 대용량 분할 업로드가 필요해질 때 도입합니다.                                           |
| 영상 일일 업로드 용량 한도                             | 남용 사례가 관찰될 때 이미지와 유사한 일일 할당량을 추가합니다.                                                                           |
