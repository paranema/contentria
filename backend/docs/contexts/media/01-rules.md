# 미디어 규칙

글 본문의 이미지를 올리고, 글과 연결하고, 쓰이지 않는 것을 치우는 규칙이다. 영상은 끝의 "영상"에 큰 방향만 적는다.

각 흐름은 위에서부터 **처음 걸리는 줄**에서 멈춘다. 흐름 3(글과 연결)만 이미지마다 줄을 적용한다.
`계층` 열이 `도메인`인 줄이 도메인 불변식이고, `앱`인 줄이 애플리케이션 정책이다.
분류 기준은 [02-implementation.md](02-implementation.md)에 있다.

## 전제

1. 이미지는 로그인한 회원이 올린다. 미디어는 회원의 계정 상태를 묻지 않는다([왜](#회원의-계정-상태를-묻지-않는다)).
2. 브라우저가 저장소에 직접 올린다. 서버는 저장소에 올릴 수 있는 짧은 주소(업로드 주소)만 내준다.
3. **이미지 주소는 업로드를 준비할 때 정해지고 바뀌지 않는다.** 글 본문에는 처음 받은 주소를 그대로 쓴다([왜](#주소는-처음부터-바뀌지-않는다)).
4. 미디어는 본문을 읽지 않는다. 본문에서 이미지 주소를 찾는 것은 출판이고, 출판이 그 목록을 넘긴다.
5. 이미지 파일은 주소를 아는 누구나 볼 수 있다. 이미지의 기록(누가 올렸는지, 어느 글에 쓰였는지)은 올린 회원만 본다.

## 처음 정하는 값

레거시에서 운영하던 값을 그대로 쓴다.

| 항목 | 값 |
|---|---|
| 형식 | JPEG, PNG, WebP, GIF |
| 크기 | 한 파일에 10MB 이하 |
| 하루 업로드 양 | 회원마다 하루(한국 시각 자정 기준)에 100MB 이하. 그날 준비해 아직 남아 있는 업로드를 센다. 거부되거나 지운 것은 빠진다(레거시와 같다) |
| 업로드 주소의 유효 시간 | 10분 |
| 글당 이미지 수 | 20개 이하. 출판의 규칙이다([publishing/01-rules.md](../publishing/01-rules.md)) |
| 완료하지 않은 업로드 | 준비한 지 24시간이 지나면 지운다 |
| 어떤 글에도 쓰이지 않는 이미지 | 그렇게 된 지 7일이 지나면 지운다 |

## 흐름 1. 업로드 준비

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 허용한 형식이 아님 | 거부 | 도메인 |
| 2 | 크기가 10MB를 넘음 | 거부 | 도메인 |
| 3 | 오늘 준비한 양에 이번 크기를 더하면 100MB를 넘음 | 거부 | 앱 |
| 4 | 그 외 | 업로드 주소(10분)와 이미지 주소를 내준다. 이미지는 "업로드 중"이다 | 도메인 + 앱 |

업로드 주소는 선언한 형식과 크기로만 올릴 수 있다. 저장소가 다른 크기와 형식을 거부한다.

## 흐름 2. 업로드 완료

브라우저가 저장소에 다 올린 뒤 알린다. 화면은 완료가 성공한 뒤에 본문에 이미지를 넣는다.

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 내가 준비한 이미지가 아니거나 없음 | 거부. 남의 이미지와 없는 이미지는 같은 응답이다 | 앱 |
| 2 | 이미 완료됨 | 성공으로 답한다. 아무것도 바뀌지 않는다 | 도메인 |
| 3 | 저장소에 파일이 없음 | 거부. 업로드 주소가 유효하면 다시 올리고 다시 완료할 수 있다 | 앱 |
| 4 | 파일의 앞부분(시그니처)이 선언한 형식과 다름 | 거부. 이미지 기록과 파일을 지운다([왜](#파일의-앞부분으로-형식을-확인한다)) | 도메인 + 앱 |
| 5 | JPEG | 사진 정보(EXIF: 위치, 기기, 촬영 시각)를 지운 파일로 같은 주소에 다시 저장하고 완료한다 | 앱 |
| 6 | 그 외 | 완료한다. 이미지는 "사용 가능"이고, 아직 어떤 글에도 쓰이지 않는다 | 도메인 |

## 흐름 3. 글과 연결

글을 저장할 때마다 출판이 그 글 본문의 이미지 주소 목록을 넘긴다. 미디어는 그 글에 연결된 이미지를 목록에 맞춘다. 몇 번을 보내도 결과가 같다.

목록의 주소마다:

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 미디어의 이미지가 아님 (다른 사이트의 이미지) | 넘어간다 | 앱 |
| 2 | 완료되지 않은 이미지 | 연결하지 않는다 | 도메인 |
| 3 | 글쓴이가 올린 이미지가 아님 | 연결하지 않는다. 그 이미지는 올린 회원의 것이다 | 도메인 |
| 4 | 그 외 | 이 글에 연결한다. 이미 연결돼 있으면 그대로다 | 도메인 |

그리고 이 글에 연결돼 있었지만 목록에 없는 이미지는 이 글과의 연결을 푼다.

한 이미지는 같은 회원의 여러 글에 연결될 수 있다. 한 글에서 빠져도 다른 글에 남아 있으면 지우지 않는다.

## 흐름 4. 글이 지워짐

출판이 글을 지운 뒤 알린다. 그 글에 연결된 이미지의 연결을 모두 푼다. 이미지는 곧바로 지우지 않고 흐름 6이 치운다.

## 흐름 5. 내가 올린 이미지 지우기

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 내가 올린 이미지가 아니거나 없음 | 거부. 남의 이미지와 없는 이미지는 같은 응답이다 | 앱 |
| 2 | 글에 연결돼 있음 | 거부. 글에서 빼고 저장하면 연결이 풀린다 | 도메인 |
| 3 | 그 외 | 파일과 기록을 지운다 | 앱 |

편집 중에 넣었다 뺀 이미지를 바로 치우는 데 쓴다. 쓰지 않아도 흐름 6이 치운다.

## 흐름 6. 정리

시스템이 주기적으로 한다.

| # | 조건 | 처리 |
|---|---|---|
| 1 | 업로드 중인 채 24시간이 지남 | 파일(있으면)과 기록을 지운다 |
| 2 | 사용 가능하지만 어떤 글에도 연결되지 않은 채 7일이 지남 | 파일과 기록을 지운다 |

파일을 지우다 실패하면 기록을 남겨 다음 정리 때 다시 지운다. 기록 없이 파일만 남는 일을 만들지 않는다.

## 다른 컨텍스트의 일로 생기는 것

| 일 | 미디어에서 |
|---|---|
| 글이 저장됨 | 흐름 3. 출판이 저장을 마친 뒤 알린다 |
| 글이 지워짐 | 흐름 4. 출판이 지운 뒤 알린다 |
| 글이 비공개가 됨 | 아무 일도 없다. 연결은 그대로다 |
| 회원이 탈퇴하거나 정지됨 | 아무 일도 없다. 정지된 회원은 글을 저장할 수 없으므로 새로 올린 이미지는 연결되지 않고 흐름 6이 치운다 |

출판이 저장을 마치고 알리기 전에 실패하면, 그 저장의 이미지는 연결되지 않은 채 남는다. 다음 저장 때 다시 맞춘다. 7일 안에 다시 저장하지 않으면 흐름 6이 그 이미지를 지우고, 본문의 그 이미지는 깨진다([왜](#글을-저장한-뒤에-연결한다)).

## 왜 이렇게 정했나

### 주소는 처음부터 바뀌지 않는다

레거시는 임시 위치(`tmp/`)에 올리고, 글을 저장할 때 영구 위치로 옮기며 본문의 주소를 바꿨다(승격).
그래서 출판의 저장이 미디어를 기다려야 했고, 저장이 실패해도 이미 옮긴 파일은 되돌아가지 않았다([strategic/05-legacy-mapping.md](../../strategic/05-legacy-mapping.md)).
주소를 처음부터 정하면 저장이 파일을 옮기지 않는다. 출판은 본문을 고치지 않고, 미디어는 연결만 맞춘다.

### 업로드를 마칠 때 검증한다

레거시는 승격할 때 파일을 검증했다. 주소가 바뀌지 않으니 그 시점이 없다.
업로드를 마친 직후에 검증하면, 본문에 들어가기 전에 잘못된 파일을 걸러 낸다. 화면은 완료가 성공한 뒤에 이미지를 넣으므로, 검증에 실패한 이미지가 본문에 남지 않는다.
레거시는 검증에 실패한 파일을 지우지 않았다. 편집기에 깨진 이미지가 남기 때문이었다. 여기서는 본문에 들어가기 전이므로 바로 지운다.

### 파일의 앞부분으로 형식을 확인한다

브라우저가 선언한 형식을 그대로 믿으면 이미지라고 선언한 HTML이 그대로 배포된다. 파일 앞의 12바이트(시그니처)로 실제 형식을 확인한다.
JPEG는 사진 정보에 위치와 기기 정보가 담기므로 다시 저장해 지운다. PNG, WebP, GIF는 다시 저장하지 않는다. GIF를 다시 저장하면 움직임이 사라진다.
근거와 대안은 [design-notes/media-upload-hardening.md](../../design-notes/media-upload-hardening.md)에 있다.

### 글을 저장한 뒤에 연결한다

글 저장과 이미지 연결은 다른 컨텍스트의 트랜잭션이다. 둘을 한 번에 성공시키거나 한 번에 되돌릴 수 없다.
저장한 뒤에 연결하면, 연결이 실패해도 남는 것은 "연결되지 않은 이미지"뿐이다. 다음 저장이 다시 맞추고, 끝내 맞추지 못하면 정리가 치운다. 되돌리는 로직이 필요 없다.
정리를 7일로 넓게 잡은 이유는, 연결이 실패한 글을 다시 저장할 기회를 주기 위해서다.

### 회원의 계정 상태를 묻지 않는다

미디어가 호출하는 다른 컨텍스트는 없다([architecture/03-context-integration.md](../../architecture/03-context-integration.md)의 "허용하는 의존"). 정지된 회원이 이미지를 올려도 글을 저장할 수 없으므로 연결되지 않고 치워진다.
정지된 회원의 업로드를 막을 필요가 생기면, 그때 회원 조회를 의존에 더한다.

## 레거시와 다른 점

| 레거시 | 여기서 |
|---|---|
| `tmp/`에 올리고 글 저장 때 영구 위치로 옮긴다 | 처음부터 영구 주소에 올린다 |
| 승격할 때 검증하고, 실패해도 파일을 남긴다 | 업로드 완료 때 검증하고, 실패하면 지운다 |
| 미디어가 본문의 마크다운 이미지 문법을 직접 찾는다 | 출판이 찾아 주소 목록을 넘긴다 |
| 한 이미지는 한 글에만 연결된다 | 같은 회원의 여러 글에 연결될 수 있다 |
| 글에서 빠진 이미지를 저장할 때 바로 지운다 | 연결만 풀고, 7일 뒤 정리가 지운다 |
| 글당 이미지 수를 미디어가 센다 | 출판이 본문으로 센다 |
| 임시 업로드는 R2 수명 규칙(24시간)이 지운다 | 미디어의 정리가 지운다. 기록과 파일을 함께 다룬다 |

## 보류

| 항목 | 사유 |
|---|---|
| 업로드 요청 수 제한 (레거시: 분당 30회, 하루 100회) | 컨텍스트와 무관한 요청 필터다. 앱에서 따로 붙인다 |
| CDN 응답 헤더 (`X-Content-Type-Options: nosniff`) | 저장소와 CDN 설정이다. 인프라 작업 때 한다 |
| 남의 이미지 주소를 본문에 붙여 넣은 경우 | 연결하지 않는다. 원래 주인의 글에서 빠지면 7일 뒤 깨진다. 문제가 되면 정한다 |
| 본문의 HTML `<img>` | 출판은 마크다운 이미지 문법(`![]()`, 참조형)만 이미지로 찾는다. HTML로 넣은 이미지는 연결되지 않아 7일 뒤 깨진다. 편집기가 HTML 이미지를 만들지 않는 동안은 두고, 필요하면 출판의 찾기를 넓힌다 |
| 큰 영상의 나눠 올리기 | 영상 묶음에서 정한다 |

## 영상

다음 묶음에서 자세히 정한다. 레거시에서 가져올 큰 방향은 다음과 같다.

| 항목 | 레거시 |
|---|---|
| 형식, 크기 | MP4, MOV, WebM, MKV. 한 파일에 500MB 이하. 길이 5분 이하 |
| 글당 영상 | 글 하나에 쓰는 영상은 하나 |
| 상태 | 대기, 변환 중, 완료, 실패, 삭제 |
| 변환 | 저장소에 원본이 올라오면 변환 프로세스가 큐에서 받아 스트리밍 형식(HLS 720p, 480p)과 포스터를 만든다 |
| 실패 | 영상이 아니거나 너무 길면 실패로 표시하고 다시 시도하지 않는다. 일시적인 실패는 큐가 다시 보낸다 |
| 정리 | 너무 오래 변환 중인 영상은 실패로, 글에 연결되지 않은 영상과 삭제한 영상은 파일과 기록을 지운다 |

영상 상태의 규칙은 업로드, 변환, 정리를 맡는 프로세스가 달라도 미디어 컨텍스트의 모델 하나에 둔다([strategic/03-bounded-contexts.md](../../strategic/03-bounded-contexts.md)).
