# 출판 규칙

블로그를 만들어 꾸리고, 카테고리를 구성하고, 글을 쓰고 발행하는 규칙이다.

각 흐름은 위에서부터 **처음 걸리는 줄**에서 멈춘다.
`계층` 열이 `도메인`인 줄이 도메인 불변식이고, `앱`인 줄이 애플리케이션 정책이다.
분류 기준은 [02-implementation.md](02-implementation.md)에 있다.

## 전제

1. 1인 블로그다. 블로그의 글은 블로그 소유자만 쓰고, 글의 작성자는 블로그 소유자다.
2. 한 회원이 블로그를 여러 개 가질 수 있다.
3. 출판은 회원을 계정 ID로만 안다. 작성자의 표시 이름과 사진은 회원이 소유하고, 화면이 조합한다.
4. 조회수는 분석이, 좋아요 수는 상호작용이 소유한다. 출판은 둘 다 저장하지 않는다.
5. 본문 형식은 마크다운이다. 출판이 소유한다.
6. **쓰는 일은 계정이 ACTIVE일 때만 한다.** 블로그 생성, 설정 변경, 카테고리 편집, 글 작성, 수정, 발행, 삭제가 모두 해당한다. 쓰기 전에 회원에게 묻는다.

## 처음 정하는 값

레거시에 없거나 레거시와 다르게 정한 값이다. 바꾸려면 이 표만 고친다.

| 항목 | 값 |
|---|---|
| 회원당 블로그 수 | 3개까지 |
| 블로그 slug | 3자 이상 30자 이하. 영문 소문자, 숫자, 하이픈 |
| 블로그 제목 | 앞뒤 공백을 뺀 뒤 1자 이상 50자 이하 |
| 블로그 설명 | 300자 이하. 없어도 된다 |
| 카테고리 이름 | 앞뒤 공백을 뺀 뒤 1자 이상 30자 이하 |
| 카테고리 깊이 | 2단계 (상위, 하위) |
| 글 제목 | 앞뒤 공백을 뺀 뒤 1자 이상 150자 이하 |
| 글 본문 | 100,000자 이하 |
| 본문의 이미지 | 20개 이하. 마크다운 이미지 문법으로 넣은 것을 모두 센다. 다른 사이트의 이미지도 센다 |
| 글 요약 | 300자 이하. 작성자가 쓰지 않으면 본문에서 앞 150자 |
| 글 slug | 100자 이하 |

## 흐름 1. 블로그 만들기

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 계정이 ACTIVE가 아님 | 거부 | 앱 |
| 2 | 그 회원의 블로그가 이미 3개 | 거부 ([왜](#회원당-블로그-수에-상한을-둔다)) | 앱 |
| 3 | slug 형식이 틀림 | 거부 | 도메인 |
| 4 | 예약된 slug | 거부 ([예약 slug](#예약-slug)) | 도메인 |
| 5 | 같은 slug의 블로그가 있음 | 거부 | 앱 + DB |
| 6 | 그 외 | 블로그, 샘플 카테고리, 샘플 글을 함께 만든다 | 앱 → 도메인 |

### 블로그

| 항목 | 규칙 | 계층 |
|---|---|---|
| slug | 영문 소문자, 숫자, 하이픈. 하이픈으로 시작하거나 끝나지 않고, 하이픈이 연달아 오지 않는다. 플랫폼 전체에서 고유하다 | 도메인 + DB |
| slug 변경 | 불가. 블로그 주소(`/@{slug}`)의 정체성이다 | 도메인 |
| 제목, 설명 | 소유자만 바꾼다. 바꿀 수 있는 것은 이 둘뿐이다 | 앱 → 도메인 |
| 소유자 | 만든 회원. 바뀌지 않는다 | 도메인 |
| 삭제 | 아직 없다 | |

### 예약 slug

회원이 가질 수 없는 블로그 주소다. 운영자의 공식 블로그나 플랫폼의 말처럼 읽히는 주소를 회원이 선점하지 못하게 한다 ([왜](#블로그-slug를-예약해-둔다)).

| 분류 | slug |
|---|---|
| 운영과 공식 | admin, administrator, root, system, staff, official, team, moderator, notice, notices, announcement, announcements, news, event, events, support, help, faq, contact, security, abuse, report, feedback |
| 서비스 경로와 계정 | api, www, app, auth, login, logout, signin, signup, register, account, settings, me, profile, dashboard, search, explore, home, about, terms, privacy, policy, status, blog, blogs, post, posts, mail, email, static, assets, cdn, media |
| 값처럼 보이는 말 | null, undefined, anonymous |
| 플랫폼 이름 | `contentria`가 들어간 모든 slug (`contentria-official`, `my-contentria` 등) |

정확히 같은 slug만 막는다. `admin-kim`, `my-notice-board`처럼 예약어를 포함하기만 한 slug는 쓸 수 있다. 플랫폼 이름만 예외로 어디에 들어가도 막는다.
예약 slug로 블로그를 만드는 일은 관리자 기능에서 한다. 아직 없다.

### 샘플

블로그를 만들면 빈 블로그 대신 구성 예시를 보여준다. 레거시와 같다.

| 항목 | 내용 |
|---|---|
| 카테고리 | `기록`(하위 `독서`), `일상` ([왜](#샘플-카테고리는-누구에게나-해당하는-주제로-한다)) |
| 글 | `독서`와 `일상`에 하나씩. 임시저장(DRAFT) 상태 ([왜](#샘플-글은-임시저장으로-만든다)) |
| 지우기 | 일반 카테고리, 일반 글과 같다. 샘플이라는 표시는 남기지 않는다 |

## 흐름 2. 카테고리 편집

카테고리는 블로그마다 하나의 트리다. 편집 화면에서 트리 전체를 고치고 한 번에 저장한다.

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 소유자가 아님 | 거부 | 앱 |
| 2 | 하위 카테고리 아래에 카테고리를 둠 | 거부. 깊이는 2단계다 | 도메인 |
| 3 | 같은 부모 아래에 같은 이름이 둘 | 거부 | 도메인 |
| 4 | 지우는 카테고리에 하위가 남음 | 거부. 하위를 먼저 옮기거나 지운다 | 도메인 |
| 5 | 지우는 카테고리에 글이 있음 | 거부. 글의 카테고리를 먼저 바꾼다 | 앱 |
| 6 | 그 외 | 저장한다 | 도메인 |

| 항목 | 규칙 | 계층 |
|---|---|---|
| 순서 | 같은 부모 아래의 표시 순서를 저장한다 | 도메인 |
| slug | 이름에서 만들고, 블로그 안에서 고유하다. 이름을 바꾸면 다시 만든다. 옛 slug는 남기지 않는다 ([왜](#카테고리-slug는-옛-주소를-남기지-않는다)) | 도메인 |
| 상위의 글 목록 | 상위 카테고리의 글 목록에는 하위 카테고리의 글도 들어간다 | 앱 |

## 흐름 3. 글 쓰기와 고치기

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 계정이 ACTIVE가 아님 | 거부 | 앱 |
| 2 | 그 블로그의 소유자가 아님 | 거부 | 앱 |
| 3 | 카테고리가 다른 블로그의 것 | 거부 | 앱 |
| 4 | 제목, 본문, 요약이 길이를 넘음 | 거부 | 도메인 |
| 5 | 그 외 | 저장한다. 새 글은 임시저장(DRAFT)으로 시작한다 | 도메인 |

카테고리 없는 글을 허용한다. 화면에는 "분류 없음"으로 보인다.

## 흐름 4. 발행과 공개 범위

| 상태 | 뜻 | 누가 보나 |
|---|---|---|
| DRAFT | 임시저장. 한 번도 발행하지 않았다 | 소유자 |
| PUBLISHED | 발행됨 | 누구나 |
| PRIVATE | 발행한 뒤 비공개로 돌렸다 | 소유자 |

| 전이 | 허용 | 계층 |
|---|---|---|
| DRAFT → PUBLISHED (발행) | 허용 | 도메인 |
| PUBLISHED → PRIVATE (비공개) | 허용 | 도메인 |
| PRIVATE → PUBLISHED (다시 공개) | 허용 | 도메인 |
| PUBLISHED, PRIVATE → DRAFT | 불가 ([왜](#발행한-글은-임시저장으로-돌아가지-않는다)) | 도메인 |

| 항목 | 규칙 | 계층 |
|---|---|---|
| 발행 시각 | 처음 발행할 때 정해지고 바뀌지 않는다. 다시 공개해도 그대로다 | 도메인 |
| 발행 알림 | 처음 발행할 때만 `PostPublished`를 보낸다. 다시 공개할 때는 보내지 않는다 ([왜](#발행-알림은-처음-발행할-때만-보낸다)) | 앱 + 이벤트 |
| 예약 발행 | 없다 | |

## 흐름 5. 글 삭제

| # | 조건 | 처리 | 계층 |
|---|---|---|---|
| 1 | 계정이 ACTIVE가 아님 | 거부 | 앱 |
| 2 | 소유자가 아님 | 거부 | 앱 |
| 3 | 그 외 | 실제로 지운다. 옛 slug도 함께 지워진다. `PostDeleted`를 보낸다 | 앱 + 이벤트 |

상호작용은 `PostDeleted`를 받아 그 글의 댓글과 좋아요를 정리한다([strategic/04-context-map.md](../../strategic/04-context-map.md)).

## 글 slug

글 주소는 `/@{블로그 slug}/{글 slug}`다.

| 항목 | 규칙 | 계층 |
|---|---|---|
| 만들기 | 제목에서 만든다. 영문은 소문자로, 공백은 하이픈으로 바꾸고, 영문 소문자, 숫자, 한글, 하이픈 밖의 문자는 지운다. 남는 것이 없으면 `post`로 한다 | 도메인 |
| 겹칠 때 | 블로그 안에서 겹치면 `-2`, `-3`을 붙인다 | 앱 + DB |
| 발행 전 | 제목을 바꾸면 slug도 다시 만든다. 아직 공유된 주소가 없다 | 도메인 |
| 발행 후 | 저절로 바뀌지 않는다. 작성자가 바꾸기로 할 때만 바뀐다. 제목에서 다시 만들게 하거나, 직접 입력할 수 있다 ([왜](#발행한-글의-slug는-작성자가-바꿀-때만-바뀐다)) | 도메인 |
| 직접 입력 | 만들기와 같은 문자만 쓴다. 하이픈으로 시작하거나 끝나지 않는다 | 도메인 |
| 옛 slug | 바뀌기 전의 slug는 옛 slug로 남는다. 옛 주소로 오면 현재 주소로 영구 이동(301)을 알린다 | 도메인 + 앱 |
| 고유성 | 블로그 안에서 현재 slug와 옛 slug를 모두 합쳐 겹치지 않는다. 다른 글의 옛 slug도 쓸 수 없다 ([왜](#다른-글의-옛-slug도-쓸-수-없다)) | 앱 + DB |
| 되돌리기 | 자기 옛 slug로는 돌아갈 수 있다. 그 slug는 옛 목록에서 빠지고 현재 slug가 된다 | 도메인 |
| 수명 | 옛 slug는 글이 지워질 때까지 남는다 | 도메인 |

## 공통

| 항목 | 규칙 | 계층 |
|---|---|---|
| 계정 상태 | 쓰기 전에 회원에게 묻는다. ACTIVE가 아니면 거부한다 | 앱 |
| 소유 확인 | 블로그, 카테고리, 글을 고치는 사람이 그 블로그의 소유자인지 확인한다 | 앱 |
| 숨긴 것의 응답 | 남의 DRAFT, PRIVATE 글은 없는 글과 같은 응답이다. 있다는 사실을 알리지 않는다 | 앱 |

## 왜 이렇게 정했나

다시 읽는 사람이 스스로 도출하기 어려운 것만 적는다.

### 회원당 블로그 수에 상한을 둔다

블로그 slug는 플랫폼 전체에서 고유하다. 상한이 없으면 한 사람이 좋은 이름을 얼마든지 선점할 수 있다.
여러 블로그를 갖는 목적(주제별로 나누기)에는 3개면 충분하다고 봤다.

### 블로그 slug를 예약해 둔다

블로그 주소는 바꿀 수 없고 플랫폼 전체에서 하나뿐이다. `@admin`, `@notice` 같은 주소를 회원이 먼저 가지면, 그 주소의 글이 운영자의 공지처럼 읽히고 나중에 되찾을 방법도 없다.
정확히 같은 slug만 막는 이유: 포함까지 막으면 `admin-kim`처럼 평범한 이름도 걸리고, 목록이 길어질수록 막히는 이름을 예측하기 어려워진다. 플랫폼 이름은 어디에 들어가도 사칭으로 읽히므로 예외로 둔다.

### 샘플 카테고리는 누구에게나 해당하는 주제로 한다

샘플은 처음 블로그를 만든 사람에게 2단계 트리와 글이 어떻게 생겼는지 보여주는 것이다. 레거시의 `기술 > 백엔드`는 개발자가 아니면 자기 블로그와 무관해 보인다.
`기록 > 독서`와 `일상`은 주제와 상관없이 누구나 쓸 법한 분류다.

### 샘플 글은 임시저장으로 만든다

샘플 글을 발행 상태로 만들면, 블로그를 만들 때마다 같은 샘플 글 두 개가 홈 화면의 "최근 발행된 글"에 올라간다. 레거시가 그랬다(`post/application/PostService.kt`의 `createSamplePosts`).
임시저장이면 소유자만 본다. 편집 화면에서 글이 어떻게 생겼는지 보여주는 목적은 그대로 지킨다. 발행하지 않았으므로 `PostPublished`도 없다.

### 카테고리 slug는 옛 주소를 남기지 않는다

카테고리 주소는 글 주소만큼 밖으로 공유되지 않는다. 옛 주소를 남기면 글과 같은 고유성 규칙과 리디렉션이 카테고리에도 필요하다.
얻는 것에 비해 규칙이 크다. 공유된 카테고리 주소가 깨지는 일이 문제로 드러나면 그때 글과 같은 방식으로 바꾼다.

### 발행한 글은 임시저장으로 돌아가지 않는다

DRAFT는 "한 번도 공개된 적 없다"는 뜻이다. 발행 전에만 slug가 제목을 따라가는 규칙이 이 뜻에 기댄다.
발행한 글을 DRAFT로 돌리면 공개된 적 있는 주소가 제목을 따라 바뀌어 옛 링크가 깨질 수 있다. 공개를 멈추려면 PRIVATE로 한다.

### 발행 알림은 처음 발행할 때만 보낸다

비공개로 돌렸다가 다시 공개할 때마다 구독자에게 새 글 알림이 가면, 같은 글의 알림을 여러 번 받는다.
발행 시각도 처음 발행할 때 정해지므로, "새 글이 나왔다"는 사건은 한 번뿐이다.

### 발행한 글의 slug는 작성자가 바꿀 때만 바뀐다

제목에서 만든 slug는 제목이 바뀌면 내용과 어긋나 보일 수 있다. 그렇다고 제목을 바꿀 때마다 slug를 바꾸면, 오타 하나를 고쳐도 주소가 바뀌고 옛 slug가 쌓인다.
그래서 발행한 뒤에는 작성자가 고르게 한다. 바뀐 slug는 옛 slug로 남겨 공유된 링크가 계속 동작하게 한다.

검토한 다른 방식은 다음과 같다.

| 방식 | 고르지 않은 이유 |
|---|---|
| 처음 발행할 때 slug 고정 | 제목을 바꾸면 주소가 내용과 어긋난 채로 남는다 |
| 주소에 바뀌지 않는 짧은 ID를 넣기 (`/@blog/posts/8kq2x/slug`) | 구현은 단순하지만 주소에 ID가 보인다. 1인 블로그에서는 깔끔한 주소의 가치가 더 크다고 봤다 |
| 제목이 바뀔 때마다 slug도 자동으로 바꾸기 | 옛 slug가 계속 쌓이고, 작성자가 모르는 사이에 주소가 바뀐다 |

### 다른 글의 옛 slug도 쓸 수 없다

옛 slug는 다른 글로 가는 리디렉션이다. 다른 글이 그 slug를 현재 slug로 가져가면, 옛 링크를 따라온 독자가 엉뚱한 글을 보게 된다.

## 레거시와 다른 점

| 항목 | 레거시 | 바뀐 규칙 | 근거 |
|---|---|---|---|
| 글 상태 | DRAFT, PUBLISHED, PRIVATE, ARCHIVED | ARCHIVED를 뺐다. PRIVATE와 다른 규칙이 없었다 | `post/domain/PostStatus.kt` |
| 조회수, 좋아요 수 | 글에 `viewCount`, `likeCount` | 뺐다. 분석과 상호작용이 소유한다 | `post/domain/Post.kt` |
| 글의 작성자 | 글에 `authorId` | 블로그 소유자로 정해지므로 따로 두지 않는다 | `post/domain/Post.kt` |
| 글 slug | 제목에서 만들고 수정할 때 덮어씀. 옛 slug 없음 | 발행 후에는 작성자가 바꿀 때만. 옛 slug로 리디렉션 | `post/domain/PostSlugGenerator.kt` |
| slug가 비었을 때 | 무작위 UUID | `post` | `global/util/SlugUtils.kt` |
| 카테고리 깊이 | 제한 없음 | 2단계 | `category/domain/Category.kt` |
| 블로그 수 | 제한 없음 | 3개 | `blog/application/BlogFacade.kt` |
| 블로그 제목 | 만들 때 받지 않음 | 만들 때 받는다 | `blog/controller/dto/CreateBlogRequest.kt` |
| 메타 제목, 메타 설명, 대표 이미지 | 글에 있음 | 지금은 없다. 대표 이미지는 미디어와 함께 정한다 | `post/domain/Post.kt` |
| 샘플 글 상태 | 발행(PUBLISHED) | 임시저장(DRAFT) | `post/application/PostService.kt` |
| 샘플 카테고리 | `기술 > 백엔드`, `일상` | `기록 > 독서`, `일상` | `category/application/CategoryService.kt` |
| 예약 slug | 없음 | 운영, 서비스 경로, 플랫폼 이름 | `blog/controller/dto/CreateBlogRequest.kt` |

근거의 경로는 태그 `legacy-final`의 `backend/blog-api/src/main/kotlin/com/contentria/api/` 아래다.
