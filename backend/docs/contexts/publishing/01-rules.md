# 출판 도메인 규칙

블로그를 개설해 운영하고, 카테고리를 구성하며, 게시글을 작성·발행하는 비즈니스 규칙을 정의합니다.

## 전제 조건

1. 모든 블로그는 **1인 블로그**입니다. 블로그의 게시글은 해당 블로그 소유자만 작성할 수 있으며, 게시글 작성자는 곧 블로그 소유자입니다.
2. 한 회원이 여러 개의 블로그를 개설할 수 있습니다.
3. 출판 컨텍스트는 회원을 계정 ID로만 식별합니다. 작성자의 표시 이름과 프로필 사진은 회원 컨텍스트가 소유하며, 화면 렌더링 시 조합합니다.
4. 게시글 조회수는 분석(`analytics`) 컨텍스트가, 좋아요 수는 상호작용(`interaction`) 컨텍스트가 각각 소유합니다. 출판 컨텍스트는 두 수치를 저장하지 않습니다.
5. 게시글 본문 형식은 마크다운(Markdown)이며 출판 컨텍스트가 소유합니다.
6. **모든 쓰기 작업은 요청자의 계정이 `ACTIVE` 상태일 때만 허용합니다.** 블로그 개설, 설정 변경, 카테고리 편집, 게시글 작성·수정·발행·삭제가 모두 해당하며, 쓰기 작업 전에 회원 컨텍스트에 계정 상태를 확인합니다.

## 기본 제약 수치

제약 기준치를 변경할 때는 아래 표의 값을 기준으로 수정합니다.

| 항목             | 기준값                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| 회원당 블로그 수 | 최대 3개                                                                                               |
| 블로그 slug      | 3자 이상 30자 이하 (영문 소문자, 숫자, 하이픈 허용)                                                    |
| 블로그 제목      | 앞뒤 공백 제거 후 1자 이상 50자 이하                                                                   |
| 블로그 설명      | 300자 이하 (생략 가능)                                                                                 |
| 카테고리 이름    | 앞뒤 공백 제거 후 1자 이상 30자 이하                                                                   |
| 카테고리 깊이    | 최대 2단계 (상위·하위)                                                                                 |
| 게시글 제목      | 앞뒤 공백 제거 후 1자 이상 150자 이하                                                                  |
| 게시글 본문      | 100,000자 이하                                                                                         |
| 본문 내 이미지   | 최대 20개 (외부 사이트 이미지를 포함하여 마크다운 이미지 문법으로 삽입된 모든 이미지를 합산)           |
| 첨부 영상        | 게시글당 최대 1개 (생략 가능, 사용 가능 여부는 [media/01-rules.md](../media/01-rules.md)의 "영상" 참고)|
| 게시글 요약      | 300자 이하 (작성자가 직접 입력하지 않으면 본문 앞 150자에서 자동 추출)                                 |
| 게시글 slug      | 100자 이하                                                                                             |

## 주요 비즈니스 흐름

출판 컨텍스트의 동작은 **블로그 개설(흐름 1) → 카테고리 트리 편집(흐름 2) → 게시글 작성·수정(흐름 3) → 발행·비공개 상태 전환(흐름 4) 및 게시글 삭제(흐름 5)**의 다섯 가지 흐름으로 구성됩니다.

- 각 흐름의 조건 표는 위에서부터 순서대로 평가하며 **처음 일치하는 조건**에서 처리를 멈춥니다.
- `검증 계층`(`담당 계층`) 열이 `도메인`으로 표기된 항목은 도메인 엔티티가 보장하는 불변식이고, `앱`으로 표기된 항목은 응용 서비스가 조율하는 애플리케이션 정책입니다.
  - 분류 기준은 [02-implementation.md](02-implementation.md) 참고

### 흐름 1. 블로그 개설

| # | 조건                                      | 처리 내용                                                      | 검증 계층   |
| - | ----------------------------------------- | -------------------------------------------------------------- | ----------- |
| 1 | 요청자 계정이 `ACTIVE` 상태가 아님        | 요청을 거부합니다.                                             | 앱          |
| 2 | 해당 회원이 이미 블로그 3개를 보유함      | 요청을 거부합니다 ([이유 참고](#회원당-블로그-수에-상한을-둔다)). | 앱          |
| 3 | 블로그 slug 형식이 유효하지 않음          | 요청을 거부합니다.                                             | 도메인      |
| 4 | 예약된 블로그 slug에 해당함               | 요청을 거부합니다 ([예약 slug](#예약-slug) 참고).              | 도메인      |
| 5 | 동일한 slug를 사용하는 블로그가 이미 존재 | 요청을 거부합니다.                                             | 앱 + DB     |
| 6 | 위 조건에 모두 해당하지 않음              | 신규 블로그와 샘플 카테고리, 샘플 게시글을 함께 생성합니다.    | 앱 → 도메인 |

#### 블로그 속성 규칙

| 항목        | 규칙                                                                                                                            | 검증 계층   |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| slug 형식   | 영문 소문자, 숫자, 하이픈(`-`)만 허용합니다. 하이픈으로 시작하거나 끝날 수 없으며, 연속된 하이픈(`--`)도 허용하지 않습니다. 플랫폼 전체에서 유일해야 합니다. | 도메인 + DB |
| slug 변경   | 변경할 수 없습니다. 블로그 주소(`/@{slug}`)의 영구적인 식별자입니다.                                                            | 도메인      |
| 제목과 설명 | 블로그 소유자만 변경할 수 있으며, 블로그에서 수정 가능한 속성은 이 두 가지뿐입니다.                                             | 앱 → 도메인 |
| 소유자      | 블로그를 개설한 회원으로 고정되며 이전할 수 없습니다.                                                                           | 도메인      |
| 삭제        | 현재 지원하지 않습니다 ([보류](#보류) 참고).                                                                                    | -           |

#### 예약 slug

일반 회원이 선점할 수 없는 블로그 주소 목록입니다. 운영진의 공식 블로그나 시스템 경로로 오인될 수 있는 주소를 회원이 등록하지 못하도록 차단합니다([이유 참고](#블로그-slug를-예약해-둔다)).

| 분류             | 예약어 목록                                                                                                                                                                                                      |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 운영 및 공식 안내| `admin`, `administrator`, `root`, `system`, `staff`, `official`, `team`, `moderator`, `notice`, `notices`, `announcement`, `announcements`, `news`, `event`, `events`, `support`, `help`, `faq`, `contact`, `security`, `abuse`, `report`, `feedback` |
| 서비스 경로·계정 | `api`, `www`, `app`, `auth`, `login`, `logout`, `signin`, `signup`, `register`, `account`, `settings`, `me`, `profile`, `dashboard`, `search`, `explore`, `home`, `about`, `terms`, `privacy`, `policy`, `status`, `blog`, `blogs`, `post`, `posts`, `mail`, `email`, `static`, `assets`, `cdn`, `media` |
| 시스템 예약 리터럴| `null`, `undefined`, `anonymous`                                                                                                                                                                                 |
| 플랫폼 브랜드명  | `contentria`가 포함된 모든 문자열 (`contentria-official`, `my-contentria` 등)                                                                                                                                    |

- 일반 예약어는 **정확히 일치하는 경우만** 차단하므로 `admin-kim`, `my-notice-board`처럼 예약어를 일부 포함한 주소는 사용할 수 있습니다. 단, 플랫폼 이름(`contentria`)은 어느 위치에 포함되더라도 모두 차단합니다.
- 예약된 slug로 공식 블로그를 개설하는 기능은 추후 관리자 기능에서 지원합니다.

#### 초기 샘플 데이터

블로그를 처음 개설하면 빈 화면 대신 블로그 구성을 바로 확인할 수 있도록 기본 샘플을 함께 생성합니다.

| 항목          | 생성 내용                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------- |
| 샘플 카테고리 | `기록` (하위 카테고리 `독서`), `일상` ([이유 참고](#샘플-카테고리는-누구에게나-해당하는-주제로-한다)) |
| 샘플 게시글   | `독서`와 `일상` 카테고리에 각각 1개씩 임시저장(`DRAFT`) 상태로 생성 ([이유 참고](#샘플-글은-임시저장으로-만든다)) |
| 수정 및 삭제  | 별도의 샘플 표식을 남기지 않으며, 일반 카테고리·게시글과 동일한 방식으로 수정하거나 삭제할 수 있습니다. |

### 흐름 2. 카테고리 편집

카테고리는 블로그마다 하나의 트리(`CategoryTree`)로 구성되며, 편집 화면에서 수정한 트리 전체를 한 번에 저장합니다.

| # | 조건                                            | 처리 내용                                                           | 검증 계층 |
| - | ----------------------------------------------- | ------------------------------------------------------------------- | --------- |
| 1 | 요청자가 해당 블로그의 소유자가 아님            | 요청을 거부합니다.                                                  | 앱        |
| 2 | 하위 카테고리 아래에 다시 카테고리를 배치함     | 요청을 거부합니다 (최대 깊이는 2단계).                              | 도메인    |
| 3 | 동일한 부모 아래에 중복된 이름의 카테고리가 있음| 요청을 거부합니다.                                                  | 도메인    |
| 4 | 삭제하려는 카테고리에 하위 카테고리가 남아 있음 | 요청을 거부합니다 (하위 카테고리를 먼저 이동하거나 삭제해야 함).    | 도메인    |
| 5 | 삭제하려는 카테고리에 속한 게시글이 존재함      | 요청을 거부합니다 (해당 게시글의 카테고리를 먼저 변경해야 함).      | 앱        |
| 6 | 위 조건에 모두 해당하지 않음                    | 변경된 카테고리 트리를 저장합니다.                                  | 도메인    |

#### 카테고리 속성 규칙

| 항목                 | 규칙                                                                                                                                                    | 검증 계층 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 정렬 순서            | 동일한 부모 카테고리 아래에서의 표시 순서를 보존합니다.                                                                                                 | 도메인    |
| 카테고리 slug        | 카테고리 이름에서 자동 생성하며 블로그 내에서 유일해야 합니다. 이름을 변경하면 slug도 새로 생성하며 이전 slug는 남기지 않습니다([이유 참고](#카테고리-slug는-옛-주소를-남기지-않는다)). | 도메인    |
| 상위 카테고리 글 조회| 상위 카테고리로 게시글 목록을 조회하면 해당 상위 카테고리에 속한 하위 카테고리의 게시글도 함께 포함됩니다.                                              | 앱        |

### 흐름 3. 게시글 작성 및 수정

| # | 조건                                      | 처리 내용                                                             | 검증 계층 |
| - | ----------------------------------------- | --------------------------------------------------------------------- | --------- |
| 1 | 요청자 계정이 `ACTIVE` 상태가 아님        | 요청을 거부합니다.                                                    | 앱        |
| 2 | 요청자가 해당 블로그의 소유자가 아님      | 요청을 거부합니다.                                                    | 앱        |
| 3 | 지정한 카테고리가 해당 블로그에 속하지 않음| 요청을 거부합니다.                                                    | 앱        |
| 4 | 제목, 본문, 요약이 제한 길이를 초과함     | 요청을 거부합니다.                                                    | 도메인    |
| 5 | 위 조건에 모두 해당하지 않음              | 게시글을 저장합니다 (신규 게시글은 항상 임시저장(`DRAFT`) 상태로 시작). | 도메인    |

- 카테고리를 지정하지 않은 게시글도 허용하며, 화면에서는 "분류 없음"으로 표시됩니다.

### 흐름 4. 발행 및 공개 범위

| 상태        | 의미                                    | 조회 가능 대상 |
| ----------- | --------------------------------------- | -------------- |
| `DRAFT`     | 임시저장 (한 번도 발행된 적 없는 상태)  | 블로그 소유자  |
| `PUBLISHED` | 발행됨                                  | 전체 독자      |
| `PRIVATE`   | 발행 이후 비공개로 전환된 상태          | 블로그 소유자  |

| 상태 전이                           | 허용 여부                                                     | 검증 계층 |
| ----------------------------------- | ------------------------------------------------------------- | --------- |
| `DRAFT → PUBLISHED` (최초 발행)     | 허용                                                          | 도메인    |
| `PUBLISHED → PRIVATE` (비공개 전환) | 허용                                                          | 도메인    |
| `PRIVATE → PUBLISHED` (재공개)      | 허용                                                          | 도메인    |
| `PUBLISHED`, `PRIVATE` → `DRAFT`    | 불가 ([이유 참고](#발행한-글은-임시저장으로-돌아가지-않는다)) | 도메인    |

| 항목          | 규칙                                                                                                                     | 담당 계층    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------ |
| 발행 시각     | 최초 발행 시점에 확정되며 이후 변경되지 않습니다(비공개 전환 후 재공개하더라도 최초 발행 시각을 유지).                   | 도메인       |
| 발행 이벤트   | 최초 발행 시에만 `PostPublished` 이벤트를 발행하며, 재공개 시에는 발행하지 않습니다([이유 참고](#발행-알림은-처음-발행할-때만-보낸다)). | 앱 + 이벤트  |
| 예약 발행     | 현재 지원하지 않습니다.                                                                                                  | -            |

### 흐름 5. 게시글 삭제

| # | 조건                                 | 처리 내용                                                                                | 담당 계층   |
| - | ------------------------------------ | ---------------------------------------------------------------------------------------- | ----------- |
| 1 | 요청자 계정이 `ACTIVE` 상태가 아님   | 요청을 거부합니다.                                                                       | 앱          |
| 2 | 요청자가 해당 블로그의 소유자가 아님 | 요청을 거부합니다.                                                                       | 앱          |
| 3 | 위 조건에 모두 해당하지 않음         | 게시글과 이전 slug 이력을 물리적으로 삭제하고 `PostDeleted` 이벤트를 발행합니다.         | 앱 + 이벤트 |

- 상호작용(`interaction`) 컨텍스트는 `PostDeleted` 이벤트를 수신하여 삭제된 게시글의 댓글과 좋아요를 정리합니다([strategic/04-context-map.md](../../strategic/04-context-map.md) 참고).

## 게시글 slug 규칙

게시글의 공개 주소는 `/@{블로그 slug}/{글 slug}` 형식입니다.

| 항목               | 규칙                                                                                                                                                              | 담당 계층   |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 자동 생성 규칙     | 게시글 제목에서 생성합니다. 영문 대문자는 소문자로, 공백은 하이픈(`-`)으로 치환하고 영문 소문자·숫자·한글·하이픈 외의 문자는 제거합니다. 남은 문자가 없으면 `post`로 대체합니다. | 도메인      |
| 중복 시 접미사 부여| 동일한 블로그 내에서 slug가 겹치면 뒤에 `-2`, `-3` 순서로 번호를 붙입니다.                                                                                        | 앱 + DB     |
| 발행 전(`DRAFT`)   | 게시글 제목을 수정하면 slug도 새 제목에 맞춰 다시 생성됩니다(아직 외부에 공유된 주소가 없기 때문).                                                                | 도메인      |
| 발행 후            | 제목을 수정해도 slug가 자동으로 바뀌지 않습니다. 작성자가 명시적으로 변경을 요청할 때만 제목 기반으로 재생성하거나 직접 입력한 값으로 변경합니다([이유 참고](#발행한-글의-slug는-작성자가-바꿀-때만-바뀐다)). | 도메인      |
| 직접 입력 규칙     | 자동 생성 규칙과 동일한 문자 집합만 허용하며, 하이픈으로 시작하거나 끝날 수 없습니다.                                                                             | 도메인      |
| 이전 slug 이력     | 변경 전의 slug는 이전 slug(옛 slug)로 보존되며, 이전 주소로 접근하면 현재 주소로 영구 이동(`301 Moved Permanently`) 응답을 반환합니다.                            | 도메인 + 앱 |
| 블로그 내 고유성   | 한 블로그 안에서 모든 게시글의 현재 slug와 이전 slug를 합쳐 중복될 수 없습니다. 다른 게시글의 이전 slug도 사용할 수 없습니다([이유 참고](#다른-글의-옛-slug도-쓸-수-없다)). | 앱 + DB     |
| 이전 slug로 복원   | 자신의 이전 slug로는 다시 되돌아갈 수 있습니다. 이 경우 해당 slug가 현재 slug로 승격됩니다.                                                                       | 도메인      |
| 이력 보존 수명     | 이전 slug 이력은 해당 게시글이 삭제될 때까지 유지됩니다.                                                                                                          | 도메인      |

## 공통 규칙

| 항목                 | 규칙                                                                                                           | 담당 계층 |
| -------------------- | -------------------------------------------------------------------------------------------------------------- | --------- |
| 계정 활성 상태 확인  | 모든 쓰기 요청 전에 회원 컨텍스트에 계정 상태를 조회하여 `ACTIVE`가 아니면 거부합니다.                         | 앱        |
| 블로그 소유권 확인   | 블로그, 카테고리, 게시글을 수정·삭제하는 요청자가 해당 블로그의 소유자인지 검증합니다.                         | 앱        |
| 비공개 리소스 응답   | 타인의 `DRAFT`·`PRIVATE` 게시글 조회 시 존재하지 않는 게시글과 동일한 응답(`404`)을 반환하여 존재 여부를 숨깁니다. | 앱        |

## 결정과 이유

### 회원당 블로그 수에 상한을 둔다

블로그 slug는 플랫폼 전체에서 유일한 자원입니다. 개설 수에 상한을 두지 않으면 한 사람이 좋은 주소를 무제한으로 선점할 수 있습니다. 주제별로 블로그를 분리해 운영하려는 용도에는 1인당 3개면 충분하다고 판단했습니다.

### 블로그 slug를 예약해 둔다

블로그 주소는 한 번 생성하면 변경할 수 없고 플랫폼 전체에서 유일합니다. 만약 `@admin`, `@notice` 같은 주소를 일반 회원이 먼저 선점하면 해당 블로그의 게시글이 공식 공지사항처럼 오인될 수 있고 사후에 회수하기도 어렵습니다.

일반 예약어에 대해 부분 일치가 아닌 **완전 일치만 차단하는 이유**는, 포함 여부까지 막을 경우 `admin-kim`처럼 일상적인 이름까지 차단되고 예약어 목록이 늘어날수록 사용자가 허용 기준을 예측하기 어려워지기 때문입니다. 단, 플랫폼 브랜드명(`contentria`)은 어느 위치에 포함되더라도 공식 계정 사칭으로 읽힐 수 있으므로 예외 없이 차단합니다.

### 샘플 카테고리는 누구에게나 해당하는 주제로 한다

초기 샘플 카테고리는 블로그를 처음 개설한 사용자에게 2단계 카테고리 트리와 게시글 구성을 보여주기 위한 예시입니다. 개발자에게만 익숙한 주제 대신 어떤 주제의 블로그에나 자연스럽게 어울리는 `기록 > 독서`와 `일상`을 기본 샘플로 제공합니다.

### 샘플 글은 임시저장으로 만든다

샘플 게시글을 발행(`PUBLISHED`) 상태로 생성하면 신규 블로그가 개설될 때마다 동일한 샘플 글 두 개가 플랫폼 홈 화면의 '최근 발행된 글' 목록에 노출되고 `PostPublished` 이벤트도 발생합니다.

임시저장(`DRAFT`) 상태로 생성하면 블로그 소유자만 볼 수 있어 에디터와 관리 화면에서 예시를 보여주는 목적을 그대로 달성하면서도 외부 목록을 오염시키지 않습니다.

### 카테고리 slug는 옛 주소를 남기지 않는다

카테고리 주소는 개별 게시글 주소만큼 외부에 직접 공유되는 빈도가 높지 않습니다. 만약 카테고리에도 이전 주소 이력을 남기려면 게시글과 동일한 이력 고유성 제약과 리다이렉트 처리가 추가로 필요해지는데, 실익에 비해 복잡도가 크므로 현재 이름 기준의 slug만 유지합니다.

### 발행한 글은 임시저장으로 돌아가지 않는다

`DRAFT` 상태는 "아직 한 번도 외부에 공개된 적이 없다"는 의미를 가지며, 제목을 수정할 때 slug가 자동으로 함께 바뀌는 규칙도 이 전제에 의존합니다.

이미 발행된 적 있는 게시글을 다시 `DRAFT`로 되돌릴 수 있게 하면, 외부에 공유된 주소가 제목 수정에 따라 예고 없이 바뀌어 기존 링크가 깨질 수 있습니다. 따라서 한 번 발행한 글을 숨기려면 `PRIVATE` 상태로 전환합니다.

### 발행 알림은 처음 발행할 때만 보낸다

게시글을 비공개(`PRIVATE`)로 돌렸다가 다시 공개(`PUBLISHED`)할 때마다 구독자에게 새 글 알림이 발송되면 동일한 글에 대한 알림이 중복 전달됩니다. 발행 시각 또한 최초 발행 시점에 한 번만 기록되므로, "새 글이 발행되었다"는 도메인 이벤트(`PostPublished`)는 최초 발행 시에만 발행합니다.

### 발행한 글의 slug는 작성자가 바꿀 때만 바뀐다

제목에서 생성된 slug는 추후 제목을 크게 고치면 주소와 내용이 어긋나 보일 수 있습니다. 반대로 제목을 수정할 때마다 slug를 자동으로 변경하면 사소한 오타 하나만 고쳐도 주소가 바뀌고 불필요한 이전 slug 이력이 계속 쌓입니다.

따라서 발행 이후에는 작성자가 명시적으로 변경을 요청할 때만 slug를 바꾸도록 하고, 변경 전 주소는 이전 slug로 보존해 기존 공유 링크가 `301` 리다이렉트로 연결되게 합니다.

검토했던 대안과 선택하지 않은 이유는 다음과 같습니다.

| 대안                                                     | 선택하지 않은 이유                                                                                             |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 최초 발행 시점의 slug를 영구 고정                        | 제목이 완전히 바뀌었을 때 주소와 글 내용이 어긋난 채로 남습니다.                                               |
| 주소에 불변 단축 ID를 포함 (`/@blog/posts/8kq2x/slug`)   | 구현은 단순하지만 URL에 무작위 식별자가 노출됩니다. 1인 미디어 블로그에서는 깔끔한 주소의 가치가 더 큽니다.     |
| 제목을 수정할 때마다 slug도 자동으로 변경                | 작성자가 의도하지 않은 시점에도 주소가 바뀌고 이전 slug 이력이 불필요하게 누적됩니다.                          |

### 다른 글의 옛 slug도 쓸 수 없다

이전 slug는 해당 게시글로 독자를 안내하는 영구 리다이렉트 경로입니다. 만약 다른 게시글이 그 slug를 자신의 현재 주소로 가져가 버리면 기존 링크를 클릭한 독자가 전혀 다른 글을 보게 되므로, 블로그 전체에서 현재 slug와 이전 slug를 모두 합쳐 고유성을 유지합니다.
