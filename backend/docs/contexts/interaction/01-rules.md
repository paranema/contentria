# 상호작용 도메인 규칙

로그인한 독자가 블로그를 구독하고 게시글에 좋아요와 댓글·답글을 남기는 비즈니스 규칙을 정의합니다.

## 도메인 개요

### 핵심 용어

상호작용 컨텍스트에서 다루는 주요 도메인 개념과 용어입니다.

| 용어                   | 의미                                                                                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 구독(`Subscription`)   | 독자가 특정 블로그의 새 글 알림을 받기 위해 맺는 관계 (구독 단위는 회원이 아닌 **개별 블로그**이며 같은 회원의 다른 블로그는 별도 구독) |
| 좋아요(`Like`)         | 독자가 발행된 게시글에 남기는 공감 표시 (게시글당 1인 1회)                                                                              |
| 최상위 댓글과 답글     | 게시글에 직접 작성한 댓글이 **최상위 댓글**이고, 최상위 댓글 아래에 1단계로 작성한 하위 댓글이 **답글**입니다.                          |
| 자리 표시(Placeholder) | 하위 답글이 달린 최상위 댓글을 삭제할 때, 답글의 대화 맥락을 유지하기 위해 본문과 작성자 정보만 비우고 남겨두는 상태입니다.             |

### 기본 원칙

1. 모든 상호작용(구독, 좋아요, 댓글 작성·수정·삭제)은 로그인한 회원만 수행할 수 있습니다.
2. 상호작용 컨텍스트는 회원을 계정 ID로, 게시글과 블로그를 각각의 ID로만 식별합니다. 작성자 표시 이름, 프로필 사진, 게시글 제목은 화면 조합 계층에서 결합합니다.
3. **새로 남기는 작업(구독 신청, 좋아요 추가, 댓글 작성·수정)은 요청자 계정이 `ACTIVE` 상태이고 대상 게시글이 발행(`PUBLISHED`) 상태일 때만 허용합니다.** 쓰기 전에 회원 컨텍스트와 출판 컨텍스트에 상태를 확인합니다.
4. **기존 기록을 거두는 작업(구독 해지, 좋아요 취소, 본인 댓글 삭제)은 계정 상태나 게시글 공개 상태를 검사하지 않습니다.** 사용자가 자신이 남긴 흔적을 지우는 행위를 막을 이유가 없기 때문입니다.
5. 블로그 소유자가 타인의 댓글을 임의로 삭제하거나 숨기는 기능은 현재 지원하지 않습니다.

### 정책 기준값

댓글 작성 및 목록 조회에 적용하는 기본 기준 수치입니다.

| 항목           | 기준값                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 댓글 본문      | 앞뒤 공백 제거 후 **1자 이상 1,000자 이하**의 일반 텍스트 (줄바꿈 유지)                                                  |
| 답글 깊이      | **최대 1단계** (답글에는 다시 답글을 달 수 없음)                                                                         |
| 댓글 목록 조회 | 최상위 댓글을 작성 시각 오름차순(오래된 순)으로 **20개씩** 조회하며, 각 최상위 댓글에 달린 답글 전체를 오름차순으로 반환 |

### 데이터 공개 범위

상호작용 데이터의 항목별 공개 대상과 조회 가능 범위입니다.

| 항목                                                  | 조회 가능 대상                                                                           |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 블로그 구독자 수                                      | 전체 공개                                                                                |
| 게시글 좋아요 수 및 댓글 수                           | 전체 공개 (댓글 수 집계 시 삭제된 자리 표시는 제외)                                      |
| 게시글의 댓글 목록                                    | 해당 게시글을 볼 수 있는 독자 (발행된 게시글이면 전체 공개)                              |
| 내가 구독한 블로그 목록, 내가 좋아요를 눌렀는지 여부  | 로그인한 본인                                                                            |
| 특정 블로그를 누가 구독했는지, 누가 좋아요를 눌렀는지 | 비공개 — 사용자용 목록 API를 제공하지 않습니다 ([배경 참고](#구독자좋아요-목록-비공개)). |

## 비즈니스 흐름

상호작용 컨텍스트의 동작은 **블로그 구독(흐름 1), 게시글 좋아요(흐름 2), 댓글 작성(흐름 3), 댓글 수정·삭제(흐름 4)**의 네 가지 흐름으로 구성됩니다. 각 흐름의 조건 표는 위에서부터 순서대로 평가하여 **처음 일치하는 조건**에서 처리를 멈추며, `검증 계층`(`담당 계층`)의 `도메인`은 도메인 엔티티가 보장하는 불변식을, `앱`은 응용 서비스가 조율하는 애플리케이션 정책을 뜻합니다([02-implementation.md](02-implementation.md) 참고).

### 흐름 1. 블로그 구독

독자가 특정 블로그를 구독하거나 기존 구독을 해지합니다. 구독 해지 요청은 현재 구독 중이지 않은 블로그이거나 존재하지 않는 블로그이더라도 성공으로 응답하며, 구독과 해지 모두 동일한 요청을 여러 번 보내도 결과가 같습니다([배경 참고](#구독좋아요-요청의-멱등성-보장)).

| #   | 조건                               | 처리 내용                                                             | 검증 계층 |
| --- | ---------------------------------- | --------------------------------------------------------------------- | --------- |
| 1   | 요청자 계정이 `ACTIVE` 상태가 아님 | 요청을 거부합니다.                                                    | 앱        |
| 2   | 대상 블로그가 존재하지 않음        | 요청을 거부합니다.                                                    | 앱        |
| 3   | 본인이 소유한 블로그임             | 요청을 거부합니다 ([배경 참고](#본인-블로그-구독게시글-좋아요-제한)). | 앱        |
| 4   | 이미 구독 중인 블로그임            | 별도 변경 없이 성공으로 응답합니다 (멱등성 보장).                     | 앱 + DB   |
| 5   | 위 조건에 모두 해당하지 않음       | 구독 기록을 생성합니다.                                               | 도메인    |

### 흐름 2. 게시글 좋아요

독자가 발행된 게시글에 좋아요를 누르거나 취소합니다. 좋아요 취소 요청은 좋아요를 누르지 않은 게시글이거나 비공개로 전환된 게시글이더라도 성공으로 응답합니다.

| #   | 조건                                               | 처리 내용                                                             | 검증 계층 |
| --- | -------------------------------------------------- | --------------------------------------------------------------------- | --------- |
| 1   | 요청자 계정이 `ACTIVE` 상태가 아님                 | 요청을 거부합니다.                                                    | 앱        |
| 2   | 대상 게시글이 없거나 발행(`PUBLISHED`) 상태가 아님 | 존재하지 않는 게시글과 동일한 응답(`404`)으로 거부합니다.             | 앱        |
| 3   | 본인이 작성한 게시글임                             | 요청을 거부합니다 ([배경 참고](#본인-블로그-구독게시글-좋아요-제한)). | 앱        |
| 4   | 이미 좋아요를 누른 게시글임                        | 별도 변경 없이 성공으로 응답합니다 (멱등성 보장).                     | 앱 + DB   |
| 5   | 위 조건에 모두 해당하지 않음                       | 좋아요 기록을 생성합니다.                                             | 도메인    |

### 흐름 3. 댓글 작성

독자가 발행된 게시글에 최상위 댓글을 작성하거나 기존 최상위 댓글에 답글을 작성합니다. 구독·좋아요와 달리 **본인의 게시글에도 댓글과 답글을 작성할 수 있습니다.** 블로그 소유자가 독자의 질문이나 의견에 답변하는 행위는 자연스러운 대화이기 때문입니다.

| #   | 조건                                                     | 처리 내용                                                 | 담당 계층       |
| --- | -------------------------------------------------------- | --------------------------------------------------------- | --------------- |
| 1   | 요청자 계정이 `ACTIVE` 상태가 아님                       | 요청을 거부합니다.                                        | 앱              |
| 2   | 대상 게시글이 없거나 발행(`PUBLISHED`) 상태가 아님       | 존재하지 않는 게시글과 동일한 응답(`404`)으로 거부합니다. | 앱              |
| 3   | 답글 작성 시 부모 댓글이 해당 게시글의 댓글이 아님       | 요청을 거부합니다.                                        | 앱              |
| 4   | 답글 작성 시 부모 댓글 자체가 이미 답글임                | 요청을 거부합니다 (답글 깊이는 1단계만 허용).             | 앱 → 도메인     |
| 5   | 답글 작성 시 부모 댓글이 삭제된 자리 표시(placeholder)임 | 요청을 거부합니다.                                        | 앱 → 도메인     |
| 6   | 댓글 본문이 비어 있거나 제한 길이(1,000자)를 초과함      | 요청을 거부합니다.                                        | 도메인          |
| 7   | 위 조건에 모두 해당하지 않음                             | 댓글을 저장하고 `CommentAdded` 이벤트를 발행합니다.       | 도메인 + 이벤트 |

### 흐름 4. 댓글 수정·삭제

작성자가 자신이 남긴 댓글이나 답글을 수정하거나 삭제합니다. 자리 표시만 남아 있던 최상위 댓글의 **마지막 답글이 삭제되면**, 더 이상 자리를 보존할 이유가 없으므로 해당 최상위 댓글 자리도 함께 삭제합니다.

| #   | 조건                                                                   | 처리 내용                                                                                                                        | 담당 계층   |
| --- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 1   | 요청자가 해당 댓글의 작성자가 아님                                     | 요청을 거부합니다.                                                                                                               | 도메인      |
| 2   | 이미 삭제되어 자리 표시만 남은 댓글임                                  | 요청을 거부합니다.                                                                                                               | 도메인      |
| 3   | **[수정]** 요청자 계정이 `ACTIVE`가 아니거나 게시글이 발행 상태가 아님 | 요청을 거부합니다.                                                                                                               | 앱          |
| 4   | **[수정]** 위 조건에 해당하지 않음                                     | 본문을 수정하고 '수정됨(`edited`)' 표시를 남깁니다.                                                                              | 도메인      |
| 5   | **[삭제]** 하위 답글이 달려 있는 최상위 댓글임                         | 레코드를 남겨두고 본문을 비워 "삭제된 댓글입니다" 자리 표시로 전환합니다 ([배경 참고](#하위-답글이-있는-댓글의-자리-표시-유지)). | 앱 → 도메인 |
| 6   | **[삭제]** 답글이 없는 최상위 댓글이거나 답글 자체임                   | 레코드를 실제로 삭제합니다.                                                                                                      | 앱          |

### 외부 상태 변경 시 데이터 처리

출판이나 회원 컨텍스트에서 게시글이나 회원의 상태가 변경되었을 때, 상호작용 컨텍스트가 기존 구독·좋아요·댓글 데이터를 어떻게 처리하는지 정의합니다.

| 외부 컨텍스트 사건              | 상호작용 컨텍스트의 처리 내용                                                                                                    |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 게시글이 비공개로 전환됨        | 기존 댓글과 좋아요를 그대로 유지합니다. 게시글 자체가 조회되지 않으므로 함께 숨겨지며, 재공개되면 다시 노출됩니다.               |
| 게시글이 삭제됨 (`PostDeleted`) | 해당 게시글의 모든 댓글과 좋아요를 삭제합니다. 이벤트가 처리되기 전에도 게시글이 이미 삭제되었으므로 외부에 노출되지 않습니다.   |
| 회원이 탈퇴함                   | 기존 구독, 좋아요, 댓글 기록을 그대로 유지합니다. 댓글 작성자 표시는 화면 조합 시 회원 컨텍스트의 탈퇴 프로필 정보로 표현됩니다. |
| 회원이 정지됨 (`SUSPENDED`)     | 기존 기록은 유지하되 새로운 구독·좋아요·댓글 작성 및 수정을 차단합니다.                                                          |

## 정책 결정 배경

### 본인 블로그 구독·게시글 좋아요 제한

구독자 수와 좋아요 수는 타인으로부터 받은 관심과 반응을 나타내는 지표입니다. 작성자 본인의 구독이나 좋아요가 포함되면 지표의 의미가 흐려지므로 본인의 블로그 구독과 본인 게시글 좋아요는 거부합니다. 반면 댓글은 독자와의 소통 수단이므로 본인 게시글에도 작성을 허용합니다.

### 하위 답글이 있는 댓글의 자리 표시 유지

답글은 부모 댓글의 맥락에 의존하는 대화입니다. 부모 댓글을 물리적으로 삭제해 버리면 남아 있는 답글이 무엇에 대한 응답인지 알 수 없게 되고, 반대로 하위 답글까지 강제로 함께 삭제하면 다른 독자가 작성한 글을 임의로 지우는 셈이 됩니다.

따라서 하위 답글이 존재하는 최상위 댓글은 본문과 작성자 노출만 지우고 자리 표시(placeholder)로 남겨 대화 맥락을 유지합니다.

### 구독자·좋아요 목록 비공개

구독과 좋아요는 독자가 부담 없이 남기는 가벼운 반응입니다. 만약 누가 구독했는지나 누가 좋아요를 눌렀는지 목록이 공개되면 독자가 반응을 남기기 전에 망설이게 될 수 있습니다. 향후 블로그 소유자용 구독자 관리 기능이 필요해지면 그때 공개 범위를 별도로 정의합니다.

### 구독·좋아요 요청의 멱등성 보장

구독 버튼이나 좋아요 버튼은 사용자가 빠르게 연속해서 클릭하거나 네트워크 재시도로 인해 중복 요청이 도달하기 쉽습니다. 두 번째 요청을 오류로 응답하면 프론트엔드 화면 상태와 서버의 실제 상태가 어긋나게 되므로, "구독된 상태로 만든다" / "구독하지 않은 상태로 만든다"와 같이 멱등(Idempotent)하게 처리합니다.

## 보류 항목

현재 단계에서는 구현하지 않고 운영 정책이나 타 컨텍스트 기능이 구체화될 때 도입할 항목입니다.

| 항목                                                | 보류 사유                                                                                                                                                             |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 좋아요 및 구독 알림 (`PostLiked`, `BlogSubscribed`) | 알림 컨텍스트에서 다건 알림 묶음 정책을 확정할 때 이벤트를 함께 추가합니다([notification/01-rules.md](../notification/01-rules.md) 참고).                             |
| 블로그 소유자의 댓글 관리(삭제·숨김)                | 플랫폼 운영 정책이 수립될 때 함께 정의합니다.                                                                                                                         |
| 탈퇴 회원의 구독을 구독자 수 집계에서 제외할지 여부 | 현재 회원 탈퇴는 타 컨텍스트로 전파되지 않으므로 집계에 포함됩니다. 알림 역시 탈퇴한 구독자 앞으로 생성되나 로그인할 수 없어 조회되지 않으며 90일 후 자동 삭제됩니다. |
| 악성 댓글 신고                                      | 운영·신고 컨텍스트가 도입될 때 정의합니다.                                                                                                                            |
