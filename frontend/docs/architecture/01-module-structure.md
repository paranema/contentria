# 모듈 구조

화면 코드를 기술 종류가 아닌 도메인 기능 단위로 분리합니다. 한 기능을 수정할 때 변경 범위를 단일 디렉터리 안으로 한정하고, 백엔드 컨텍스트 변경 시 대응하는 프론트엔드 모듈을 즉시 찾을 수 있도록 구성합니다.

## 디렉터리 구성

```text
src/
├── app/                     라우팅, 레이아웃, 여러 기능 모듈의 화면 조합
│   ├── _composition/        여러 기능의 서버 API를 조합하는 함수 (비라우트)
│   ├── _components/         여러 라우트 그룹이 공유하는 조합 컴포넌트 (푸터, 프로필 메뉴 등)
│   └── <경로>/_components/  해당 경로 하위에서만 사용하는 조합 컴포넌트
├── features/
│   └── <기능>/
│       ├── api/             Server Actions 및 서버 전용 API 호출 함수
│       ├── types.ts         기능 전용 요청·응답 타입 (또는 types/ 디렉터리)
│       ├── hooks/           TanStack Query 훅 및 화면 상태 훅
│       └── components/      단일 기능에 속하는 UI 컴포넌트
├── shared/
│   ├── api/                 apiServer, ApiError, ActionResult, 세션 쿠키 중계
│   ├── config/              런타임 환경 변수 조회
│   ├── ui/                  shadcn/ui 기본 컴포넌트
│   ├── components/          도메인과 무관한 공용 컴포넌트 (테이블, 페이지네이션 등)
│   ├── providers/           전역 Context Provider (React Query, 공개 설정)
│   ├── lib/                 날짜 포맷, 클래스 병합 등 범용 유틸리티
│   └── constants/           경로 상수
├── types/                   전역 환경 변수 타입 선언
└── proxy.ts                 요청별 세션 토큰 갱신 및 보호 경로 접근 제어
```

- 기능 모듈 내부의 하위 폴더는 실제로 필요할 때만 생성하며, 빈 폴더를 미리 두지 않습니다.
- 밑줄(`_`)로 시작하는 `app/` 하위 폴더는 Next.js 라우팅 대상에서 제외됩니다.

## 기능 모듈

`src/features/` 하위 모듈은 백엔드의 6개 바운디드 컨텍스트([backend/docs/strategic/03-bounded-contexts.md](../../../backend/docs/strategic/03-bounded-contexts.md))와 1:1로 대응합니다.

| 기능 모듈      | 대응 컨텍스트  | 담당 범위                                                      |
| -------------- | -------------- | -------------------------------------------------------------- |
| `member`       | `member`       | 회원가입, 로그인, 세션, 프로필, 계정 설정                      |
| `publishing`   | `publishing`   | 블로그 개설, 카테고리 트리, 게시글 에디터, 공개 블로그·글 조회 |
| `interaction`  | `interaction`  | 블로그 구독, 게시글 좋아요, 댓글, 집계 수 조회                 |
| `notification` | `notification` | 알림함 조회 및 읽음 처리                                       |
| `media`        | `media`        | 이미지·영상 직접 업로드, HLS 영상 플레이어                     |
| `analytics`    | `analytics`    | 방문 기록 전송, 통계 대시보드                                  |

## 의존 규칙

허용되는 참조 방향은 `app → features → shared` 단방향입니다.

| 규칙                                                                               | 목적                                                                              | 검증 수단                      |
| ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------ |
| `features/<A>`는 `features/<B>`를 import하지 않습니다.                             | 기능 간 결합을 차단합니다(백엔드 `-core` 간 직접 의존 금지와 동일).               | ESLint `no-restricted-imports` |
| `shared/`는 `features/`와 `app/`을 import하지 않습니다.                            | 공용 코드가 특정 도메인이나 화면에 종속되지 않도록 보호합니다.                    | ESLint `no-restricted-imports` |
| `features/`는 `app/`을 import하지 않습니다.                                        | 하위 모듈이 상위 페이지 조립 계층에 역의존하지 않도록 합니다.                     | ESLint `no-restricted-imports` |
| 모듈 외부 경로를 참조할 때는 `@/` 별칭을 사용합니다.                               | 상대 경로(`../../`)로 ESLint 경로 패턴 검사를 우회하는 일을 방지합니다.           | 코드 리뷰                      |
| 백엔드 API는 각 기능의 `api/`에서 `apiServer`로만 호출합니다.                      | 기본 주소, 인증 헤더, 오류 변환 규칙을 단일 지점에서 관리합니다.                  | 코드 리뷰                      |
| JSX 마크업을 포함하는 최상위 폴더는 `tailwind.config.ts`의 `content`에 등록합니다. | 누락된 폴더에서만 쓰인 유틸리티 클래스가 스타일시트에서 빠지는 문제를 방지합니다. | 설정 관리                      |

## 화면 조합

여러 컨텍스트의 데이터나 UI 동작을 한 화면에 모아야 할 때는 성격에 따라 세 위치로 나누어 처리합니다.

| 조합 위치                                 | 사용 기준                                                                          | 대표 사례                                                                                           |
| ----------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 백엔드 `apps/api` 조합 API                | 권한이나 공개 여부를 먼저 검증한 뒤에만 다른 컨텍스트 데이터를 내려줄 수 있는 경우 | 블로그 대시보드(소유자 확인), 게시글 첨부 영상 조회                                                 |
| `app/_composition/` 서버 함수             | 공개 데이터를 화면 단위로 묶어 조회하는 경우                                       | 블로그 레이아웃(블로그 + 카테고리 + 소유자 프로필), 댓글 목록과 작성자 프로필 병합                  |
| `app/**/_components/` 클라이언트 컴포넌트 | 한 기능의 컴포넌트에 다른 기능의 클라이언트 함수나 UI 슬롯을 주입해야 하는 경우    | 출판 에디터(`PostEditorClient`)에 미디어의 이미지 업로드 함수와 영상 업로더를 결합하는 `PostEditor` |

- `app/_composition/`에서 목록 데이터를 조합할 때는 작성자 ID를 모아 회원 프로필을 일괄 조회함으로써 N+1 호출을 방지합니다.
- 동일한 요청 안에서 레이아웃과 페이지가 함께 호출하는 조합 함수(예: `getBlogLayoutData`)는 React `cache()`로 감싸 요청당 한 번만 실행합니다.
